# 具体功能分析模板

该模板规定具体功能模式的固定输出结构。最终文档必须与
`SupportClient/总领文档/基础工程与运行环境/网络模块需求.md` 保持相同的分析逻辑和章节节奏，不能只输出通用需求摘要。

```markdown

说明业务目标、用户价值、适用范围、模块边界和当前实现范围。

## 每个能力分节的强制内容

每个能力分节必须同时回答：

1. 为什么存在以及服务哪个业务场景。
2. 接收什么输入，产出什么输出。
3. 由哪个入口触发，经过哪些调用层。
4. 哪些代码已经实现，哪些只是缺口或建议。
5. 失败、重试、取消、并发和清理如何处理。
6. 数据由谁持有、持久化和清理。
7. 如何通过业务结果、错误行为和测试验收。

网络模块的“模块目标、模块结构、能力分节、验收标准、技术细节与设计代码位置、整体业务流程、状态/数据/错误/边界/测试/演进”顺序是所有具体功能文档的统一标准。功能复杂度只能影响能力分节数量，不能改变上述主结构。
