# 模块主体需求文档清单格式

项目总领模式默认按“一级核心模块”创建一个需求文档，不再为每个细分功能分别创建 `.md` 文件。

每行填写一个模块，使用 `|` 后列出该模块覆盖的主要功能：

```text
会话与认证 | Apple 登录；验证码登录；设备游客账号；Token 持久化；会话恢复与退出
AI 设置 | 模型管理；Provider 与 API Key；运行时配置；本地持久化
文件与 OSS | 文件上传下载；STS 凭证；文件缓存；业务绑定
内容与公开分享 | 文件目录；文章管理；内容发布；公开分享
```

脚本会创建一个主体文档，并将功能直接写入文档：

```text
总领文档/
├── 会话与认证/
│   └── 会话与认证需求.md
├── AI 设置/
│   └── AI 设置需求.md
└── 内容与公开分享/
    └── 内容与公开分享需求.md
```

主体文档结构为：

```markdown
## 三、功能模块

### 3.1 [Apple 登录](#apple-登录)

#### 需求说明
#### 基础要求
#### 验收标准
#### 技术细节与设计代码位置
```

每个功能只作为主体文档内的一个模块，不创建对应的独立 `.md` 文件。

规则：

- 默认一行一个一级核心模块。
- 功能之间可使用 `；`、`、`、`,` 分隔。
- 模块名可以包含空格和中文，但不能包含 `..` 或反斜杠。
- 已有主体 `.md` 文件只报告 `EXISTS`，不覆盖、不清空；需要重新生成时显式使用 `--force`。
- 不创建 `模块/功能/功能需求.md` 这种细粒度文件。
- 功能模块固定生成“需求说明、基础要求、验收标准、技术细节与设计代码位置”四个小节。
