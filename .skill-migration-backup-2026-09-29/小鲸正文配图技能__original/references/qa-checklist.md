# QA Checklist

## 必过项

- 是 16:9 横版。
- 背景是干净白底。
- 有小鲸。
- 小鲸承担核心动作，不只是装饰。
- 小鲸有清晰识别点：喷泉。
- 小鲸保留白肚纹、短手短脚、尾鳍。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面亲和、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色用于小鲸主色、补充说明、反馈或系统状态，但不要把整张图做成拥挤蓝色海报。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 出现小黑、黑色怪物、黑豆或影子人。
- 小鲸像普通真实鲸鱼、海豚、鱼、海豹或蓝色圆球。
- 小鲸缺少喷泉、白肚纹、短手短脚或尾鳍。
- 小鲸像贴纸、表情包或低幼儿童角色。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 背景被海底、沙滩、珊瑚、棕榈树等装饰塞满。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有角色动作或视觉隐喻。
- 和 `assets/examples/` 里的旧案例构图过于相似。

## 迭代方法

- 太普通：让小鲸成为动作主体，加入一个清爽但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太幼稚：强调 clean 2D animation concept art、friendly but not childish、not sticker sheet。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和小鲸动作。
- 角色漂移：强化 recognition word: 喷泉，并补充 white striped belly, short arms and legs, small tail fin。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先认出“小鲸”，然后 1 秒内看懂结构。

如果第一眼像教程页、贴纸包或设定板，而不是一张正文解释图，就不合格。
