# 细粒度功能需求文档清单格式

该格式只用于用户明确要求“每个功能单独建立需求文档”的场景。项目总领模式默认使用
`references/module-doc-stub-format.md`，按一级核心模块合并创建主体文档。

需要拆分专项文档时，每行填写一个相对于 `总领文档/` 的文档路径：

```text
内容与公开分享/文件目录/文章管理
内容与公开分享/文件目录/公开分享
账号与认证/登录与会话
账号与认证/设备会话
```

脚本会创建：

```text
总领文档/
├── 内容与公开分享/
│   └── 文件目录/
│       ├── 文章管理.md
│       └── 公开分享.md
└── 账号与认证/
    ├── 登录与会话.md
    └── 设备会话.md
```

规则：

- 每行对应一个主要功能需求文档。
- 可以带 `-`、数字编号或 `*` 前缀。
- 可以在行尾追加 `|` 说明，脚本只使用左侧路径。
- 可以写 `.md` 后缀，也可以省略；脚本会统一补 `.md`。
- 路径只能位于 `总领文档/` 内，不允许 `/` 开头、`..`、反斜杠或空路径段。
- 已有文件只报告 `EXISTS`，不覆盖原文档。
- 新文件为空初始化文件，后续由具体功能分析模式填充。

示例：

```bash
printf '%s\n' \
  '内容与公开分享/文件目录/文章管理' \
  '内容与公开分享/文件目录/公开分享' \
  '内容与公开分享/文件目录/内容版本' | \
  bash scripts/create_feature_doc_files.sh \
    --docs-root /path/to/Project/总领文档 \
    --stdin
```
