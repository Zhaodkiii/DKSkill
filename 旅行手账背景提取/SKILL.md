# 旅行手账背景提取

从一张已完成的手账内页中，提炼出"带装饰的空白底图"，用于后续重新排版照片和文字。

## 胶带硬性要求

**背景内明确不要胶带。全部胶带、格纹条、半透明条、边缘残片、残胶、粘贴阴影和压痕必须清除。不得把胶带融入纸纹，不得保留为照片位置标记，也不得因胶带贴在花叶或插画上而保留。清除后补全下方纸纹、花叶与线描；任何胶带残留都判定为未完成。每次生成提示和验收都必须包含此要求。**

## 一、什么是"背景"——核心概念

背景不是一张纯色纸，而是**去掉"可替换内容"（照片、文字）之后，页面上剩余的一切**。它决定了手账的整体氛围、材质感和装饰骨架。

详细的元素分类判定（哪些保留、哪些去除、为什么）见：
**[references/元素分类判定清单.md](references/元素分类判定清单.md)** —— 每次处理前对照此清单逐项识别。

简要分类：

| 分类 | 包含内容 | 处理 |
|---|---|---|
| **纸张底色层** | 做旧米黄色牛皮纸纹理、纸张纤维质感、边缘做旧暗化 | 保留 |
| **水彩/插画层** | 蓝色水彩晕染、海景水彩、窗景插画、礁石海浪插画 | 默认保留（除非用户点名去掉） |
| **装饰线描层** | 飞鸟、海浪波纹、帆船、灯塔、指南针、植物枝叶、虚线路线、邮戳、邮票齿孔 | 保留 |
| **实物装饰层** | 干花枝条、贝壳、海玻璃、金色船锚、麻绳结 | 保留 |
| **胶带与粘贴痕迹** | 所有颜色的胶带、半透明条、格纹条、残胶、压痕和投影 | 必须全部去除；禁止融入背景或作为照片位置标记保留 |
| **照片层** | 所有相框内的图像（风景照、人物照、胶片照） | 去除 |
| **文字层** | 标题、正文、标签文字、日期、页码、填空下划线 | 去除 |
| **标签框/便签** | 带金属孔的空标签框、撕边便签形状 | 默认去除（除非用户要求保留形状） |

## 二、完整工作流

**单次生成规则：每张源图只调用一次 image_edit，只产出一张背景；同批次多张源图分别各调用一次。调用前完成所有元素识别并一次性写全提示词。生成后不得为同一源图重试、微调或再次生成；缺陷如实记录并在交付说明中指出。**

### Step 1 — 读图，逐项分类

1. 用 `Read` 打开用户指定的手账内页（`thumbnail_size="large"`）。
2. 对照 [元素分类判定清单](references/元素分类判定清单.md)，在心中列出：
   - 照片清单：每张照片在什么位置、内容是什么
   - 文字清单：每处文字的原文（标题、正文、标签、页码）
   - 去除清单：所有胶带的位置，包括边缘残片、压在花叶上的胶带及半透明粘贴痕迹
   - 装饰清单：所有线描、干花、贝壳、海玻璃、插画的位置
3. 如果用户在消息中点名了"XX 要保留/去掉"，记录为特殊要求，优先级高于默认规则。

### Step 2 — 获取图片 URL

`image_edit` 需要 URL 传入参考图。

- 如果用户提供的是 URL，直接使用。
- 如果是本地文件，调用 `FileBatchUpload` 上传获取 URL。
- 上传超时（文件较大时可能发生）：可尝试使用历史生成该图时返回的 URL，或让用户确认后重试。

### Step 3 — 用 image_edit 提炼背景

**每张原始内页图严格只调用一次 image_edit。** 先完成照片、文字、标签、胶带及保留装饰的完整盘点，再一次性写全提示词。不要因为生成结果不理想而重复生成。

调用 `image_edit`，参考图 = 手账内页 URL。Prompt 必须按以下结构组织：

**生成结果必须在这一次调用返回后立即落盘。** 若工具返回 `data:` 图片 URL，先将其解码写入临时 PNG；若返回可下载 URL 或本地文件路径，立即下载/复制到临时 PNG。不得只展示生成结果、丢弃返回值或等到后续步骤再找回。只有临时文件已存在且 `file` 确认为有效图像后，才算本页生成完成；保存/解码失败时停止并如实报告，不能再调用生成工具绕过单次限制。

1. **开头说明任务**："将这张手账[左/右]页进行编辑"
2. **去除清单（逐项具体列出）**：
   - 所有照片：描述位置和内容，如"上方大幅风车山线照片""左下角渔民作业照片"
   - 所有文字：逐条列出原文，如"大标题'XXX'""标签文字'XXX'""页码'02—03'"
   - 标签框/便签（如默认去除）
   - 全部胶带与粘贴痕迹：逐处说明位置；连同格纹、半透明色块、残胶、阴影、压痕一起清除。被遮挡的纸纹、花叶和线描自然重建，不留下空白矩形或胶带轮廓
   - 明确写："去除后自然露出下面的做旧米黄色牛皮纸底色"
3. **保留清单（逐项具体列出，这是核心）**：
   - 纸张底色和做旧质感
   - 每条装饰线描的位置和内容
   - 干花、贝壳、海玻璃、船锚等实物装饰；胶带禁止保留
   - 水彩插画（如果保留）
4. **去白边硬要求（必须写入）**：
   > "画面四边就是纸张边缘，绝对不存在任何白色背景、白色边框、外围留白。不要把纸放在桌面或白色背景上，不展示书本、不展示环境——这是一张纯平面的、占满整个画布的手账内页扫描件。"
5. **结尾**："输出一张手账页背景底图，有[保留的装饰]，但没有照片、没有文字、无任何白边。"

**Prompt 模板见** [references/prompt模板.md](references/prompt模板.md)。

**关键经验：**
- 保留/去除清单必须具体到"哪个位置、什么内容"，不能只写"参考原图"。
- 模型常在四周残留 3~10px 白边，去白边措辞不能省。
- 同一源图禁止迭代生成。除规格统一外，生成后不再编辑图像内容；结果不理想时如实记录，不重复调用 image_edit。

### Step 4 — 后处理（统一规格 + 白边检测）

将已落盘的临时生成图交给后处理脚本（支持本地路径）：

```bash
python3 scripts/process_background.py "<临时生成图路径或生成图URL>" "<输出路径>" --width <原图宽> --height <原图高> --dpi <原图DPI>
```

脚本自动完成：下载 → 白边检测并报告 → 转 PNG → 缩放到目标尺寸 → 写入 DPI。

**重要：输出规格必须与原图完全一致。** 处理前先确认原图的：
- 像素宽高（`sips -g pixelWidth -g pixelHeight`）
- DPI（`sips -g dpiWidth -g dpiHeight`）
- 格式

本项目默认印刷规格（如原图为此规格则输出一致）：

| 参数 | 值 |
|---|---|
| 像素 | 2185 × 3130 px（竖版） |
| DPI | 300 |
| 物理尺寸 | 18.5 × 26.5 cm |
| 格式 | PNG |

若脚本报告"⚠ 检测到白边"（任一边 >3px），保留生成结果并在交付说明中指出；单次生成规则下不得再次生成，也不得裁切掩盖明显白边。

### Step 5 — 验证

交付前确认：
1. 输出文件存在，格式为真正的 PNG（`file <路径>` 应显示 "PNG image data"，不能是 JPEG 套 .png 后缀）。
2. 像素尺寸与原图一致。
3. DPI 与原图一致（脚本写入 pHYs chunk，`sips -g dpiWidth` 可查）。
4. 四角像素不是纯白色（可用脚本白边检测结果确认）。
5. 用户点名保留/去除的元素已按要求处理。
6. 逐处检查原胶带位置及四边，记录是否有胶带残片、格纹条、半透明色块、残胶、投影或压痕。发现残留时如实说明，不得重生成。

### Step 6 — 交付

- 使用当前环境实际可用的文件交付能力交付成品；若无专用交付工具，提供指向已保存成品的 Markdown 本地文件链接，并可用 `open_in_codex` 打开预览。不得声称已交付未落盘的图。
- 一次只交付一张；多张背景逐张生成、逐张交付。
- 交付说明简要列出：保留了什么、去掉了什么、保存在哪里。

## 三、文件存储位置

```
<原图所在目录>/
├── <原图文件名>.png          （原始手账内页）
└── 背景/                     （背景子目录，不存在则创建）
    └── <原图文件名去掉扩展名>-背景.png
```

**命名规则：**
- 单页背景：`<原内页文件名>-背景.png`
  - 例：`花鸟岛-灯塔替我们守着夜晚-右页背景.png`
  - 例：`枸杞岛-海面上也有田野-左页背景.png`
- 如果同一页有多版（如纯纹理版 vs 带插画版），在文件名中区分：
  - `枸杞岛-牛皮纸背景.png`（纯纹理）
  - `枸杞岛-海面上也有田野-左页背景.png`（带插画）

**示例完整路径：**
```
/Users/hua/Documents/project/TravelDiary/舟山/成品/09_枸杞岛/
├── 枸杞岛-海面上也有田野-手账左页.png
├── 枸杞岛-海面上也有田野-手账右页.png
└── 背景/
    ├── 枸杞岛-海面上也有田野-左页背景.png
    └── 枸杞岛-海面上也有田野-右页背景.png
```

## 四、单次生成规则

- 每张源图在整个任务中只生成一次背景；不同源图各自生成一次。
- 不因白边、胶带残留、内容遗漏或用户微调要求再次生成；生成后只做尺寸、格式、DPI统一。
- 将发现的问题写入交付说明。只有用户明确要求例外并撤销单次限制时，才可重新生成。
