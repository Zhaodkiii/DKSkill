# 图片分层 PSD 重建

## 目标

把一张 JPG/PNG 扁平图重建为可在 Photoshop 正常打开的 PSD：

- 画布尺寸与原图一致。
- 背景和可独立移动的视觉元素分别成层。
- 标题、副标题、正文、日期和说明文字全部按逻辑块或原始行拆成独立图像层，方便后期移动、缩放、调色和替换。
- 每份 PSD 必须含独立可见的主题 Logo，交付 PNG 时也必须保留 Logo；按上方「每份成品必有主题 Logo」生成或复用并放置。
- 所有图层使用简体中文名称。
- 首次生成本页面只交付一个正式 PSD；共享章节目录中的其他页面或历史 PSD 必须保留。后期局部改动可保留多个有明确改动范围的 PSD 版本。交付目录不放 PNG、JSON、JSX 和脚本副本；原始素材与源稿副本归入素材库。

本技能追求“结构可编辑且视觉接近”，不是恢复原作者未提供的真实源文件。`image_gen` 隔离元素允许轻微重绘，但必须优先保持原位置、尺寸、方向和视觉中心。

## 每份成品必有主题 Logo

### 来源与生成

- 必用关联技能：[寻寻仔主题Logo生成](/Users/hua/Documents/Skill/寻寻仔主题Logo生成/SKILL.md)。生成前读取该技能并执行它的基础 Logo 读图、主题判断、单次生成、真实透明度和视觉验收规则。
- 原稿没有 Logo、用户只要求背景或照片拆层、已有背景、未再次提及品牌，都不能省略 Logo。左右单页、跨页、多个主题或多个输出文件逐份检查；不能只给其中一份放 Logo，也不能只交付独立 Logo PNG 而没有合入 PSD。
- 用户指定了 Logo 文件：先实际查看并检查，合格则直接复用原文件；不得擅自换成其他版本、改字或重绘。发现光晕、雾底、主题不符等缺陷时如实说明，遵循用户后续明确选择，不把不合格文件静默当作合格素材。
- 没有指定合格文件时，先检查已有同主题合格透明 Logo；可用则复用，缺失则按关联技能生成一张。不同页面主题分别匹配 Logo，同主题左右页可以复用同一份合格素材。
- 默认只有图形，不含「寻寻仔」「TRAVEL DIARY」或其他文字；保留打开的书、双眼、圆头虚线路线、右页单红点与深绿线条，仅加入一至两个页面主题意象。
- Logo 的单次生成限制优先于本技能普通组件的重试规则：同一用户请求最多调用一次；不合格时保留结果并报告，不能自动重试或无 Logo 交付。批量不同主题优先匹配已有合格素材，不能把一次生成擅自扩成多个 Logo；尚未取得合格 Logo 的文件不得当作完成稿交付。用户明确要求重新生成才开启新一次调用；不影响其他已合格素材的复用。

### 合适位置必须按当前页面决定

1. 实际查看原稿和背景，优先选择有留白、对比清楚的纸面、页角或信息区边缘。不要默认压在池水、树林等复杂照片上，也不要固定套用右下角。
2. 在版式测量表中增加 Logo 的 `x/y/width/height`、有效 Alpha 宽高比、层级、周围留白，以及选择此处的理由。位置为新增加的品牌落款时明确记录，不伪称原稿已有位置。
3. 以画布短边约 6%–10% 的宽度作为起点，等比缩放，再按该图形的识别度调整；与裁切边、书脊/跨页折线和附近内容保留安全距离，通常至少短边的 2%。这些是起点，不是固定坐标。
4. 不遮挡标题、正文、照片主体、原有印章或关键插画；前景卡片也不能盖住 Logo。背景对比不足时换位置，不用发光、雾底、大投影或任意改色补救。
5. Logo 必须单独成普通图像层，命名 `品牌Logo_<中文主题>`，标记 `"role": "brand_logo"`，设置紧边界目标 `box`，保持可见；合成脚本把该层置于顶部并保留 100% 图层不透明度。
6. 位置是否合适先依据读图、测量和邻近组件框判断；文件级检查只证明图层、可见状态、比例和边界，不能宣称已通过整页视觉验收。用户要求检查最终效果时才额外看整页预览。

本节与适量素材版本的 Logo 处理规则一致，优先于下文通用隔离、白底处理和重试规则。独立主题 Logo 允许紧边界透明 PNG，通过 `box` 定位；不要求完整原位画布、不执行去白。重建版原有的整页预览、OCR、照片拆层与 Photoshop 实开验收仍照常执行；本节第 6 项仅表示 Logo 检查本身不另行增加整页预览。

## 强制架构：JSON Bridge

必须严格按以下顺序执行，不得交换阶段：

1. `image_gen / Images 2.0`：生成完整不透明背景、非文字元素及全部文字块的隔离图；独立元素优先真实透明 PNG。
2. Python：尺寸统一、保留真实 alpha（白底例外执行边缘连通去白）、OCR 语义校验、Unicode 校验并写入 UTF-8 `manifest.json`。
3. Node.js：只读取 `manifest.json`，生成临时 JSX 并调用 Photoshop 合成 PSD。
4. Photoshop：实开 PSD，验证尺寸、图层、透明度和文字图像层。
5. 清理交付目录，只留下正式 PSD 和已明确命名的后期版本 PSD。

禁止：

- 跳过阶段 1，直接用本地抠图或原图切片伪造元素分层。
- 用 OpenCV、Pillow、Photoshop 选区替代 `image_gen` 进行元素来源拆分。
- 第一阶段之前做 manifest、PSD 合成或检查 API Key/SDK/CLI fallback。允许对原图做只读 OCR、尺寸测量与裁切预览，不能把原图裁片作为素材。
- 创建 Photoshop Type Layer，或为了可编辑而用近似字体替代原图文字。
- 在 shell、PowerShell 参数或内联脚本中直接拼接用户提供的中文正文；中文通过 UTF-8 JSON 传递。
- 交付 PSD 之外的任何中间文件。

如果内置 `image_gen` 无法调用，立即停止并说明：“无法执行阶段 1”。不要使用替代方案。

## 开始前确认

从用户请求和附件确定：

- 原图绝对路径。
- 最终目录和 PSD 文件名。
- 原图像素尺寸；除非用户另有要求，PSD 保持同尺寸。
- 是否要求特定印刷尺寸/DPI。
- Photoshop 应用名称；macOS 通常为 `Adobe Photoshop 2026`。

创建两个目录：

- ASCII 临时工作目录，例如 `/tmp/psd_rebuild_<id>`，用于所有中间文件。
- 用户指定的新交付目录，最终只放 PSD。

同时确定项目素材库路径，按以下顺序处理：

1. 用户本次或此前在同一任务中指定的路径优先，授权持续有效，不重复询问。
2. 沿用项目已有素材库及其章节、页面、分类结构。原图位于 `<旅行项目>/成品/` 时，先检查 `<旅行项目>/素材库`，不要只搜索 `成品/` 内部，也不要另建平行素材库。
3. 没有用户指定路径且确实找不到项目素材库时，才在生成前确认一次建议目录。

保留原图已有 DPI；未知且用户未指定时才采用 300 DPI，并记录这个假设。素材库与交付目录分离，不影响“交付目录只保留 PSD”的要求。

不要在原图目录散落中间文件。

### 原图文字与几何清单（只读）

- 先看完整原图，再用现有 OCR 工具读取全部标题、副标题、正文与便签，按原图逐字复核。macOS 可使用 Vision；不要为 OCR 临时安装新依赖。
- 将每个文字块的原文记为 `expected_text`，保留简繁、标点和原始行序。不能凭地名常识或 OCR 单次结果猜字。
- 对形近字、低置信度文字放大原图预览核对，如“衢／衡／衝”和“岛／島”。清单与原图文字块数量必须一致，避免漏掉底部或边缘标签。
- 测量每个独立目标的原图占位框 `[left, top, right, bottom]`。画布纵横比一致不代表元素大小或位置一致。
- 原图预览裁切只供观察，不能参与后续分层合成；所有素材像素仍必须来自 image_gen。

macOS 可直接使用技能内的 Vision OCR，输出真实识别文字、置信度和以左上角为原点的归一化占位框：

```bash
swift /绝对路径/图片分层PSD重建/scripts/ocr_text.swift \
  /原图绝对路径.png /生成文字素材绝对路径.png > /tmp/psd_rebuild_x/ocr.json
```

OCR 坐标仅辅助测量文字，不等于纸签或完整组件的边界；必须按原图人工确认。置信度高也不能省略形近字复核。

### 后期局部改动流程

用户要求修改已交付 PSD 中的文字、标签或单个元素时，不重做整页：

1. 确认正式 PSD、目标图层名、新内容和新版本文件名。
2. 检查新版本路径不存在；若已存在，追加日期或序号，禁止覆盖。
3. 将正式 PSD 复制为新版本，保留所有原图层、顺序、坐标、尺寸和效果。
4. 只对本次改动的文字、标签或元素执行阶段 1 生成；不重新生成背景或其他未改动图层。
5. 对新生成图层执行阶段 2 的透明化、OCR 语义和 Unicode 校验。
6. 通过 Node.js 临时 JSX 在新版本 PSD 中按图层名精确替换目标图层；新图层继承原图层的中心位置、显示尺寸、顺序和名称。
7. 若找不到唯一的同名目标图层，立即停止，不得猜测替换。
8. 只在 Photoshop 实开验收新版本，同时确认正式 PSD 的文件修改时间和内容未变。

局部改动仍必须遵守 JSON Bridge；manifest 只列出本次替换的图层，并额外包含 `source_psd`、`output`、`target_layer_name` 和 `change_scope`。

## 阶段 1：全部视觉元素生成

### 1. 先列拆分清单

在 commentary 中先列出主要非文字元素，再单列全部文字图层。非文字元素通常不超过 10 个；文字层按原图实际行数拆分，不受此数量限制。

典型拆分顺序：

1. 完整背景：底色、纸张、固定纹理、不可独立移动的细小装饰；清除所有计划独立成层的文字。
2. 主体或人物。
3. 前景。
4. 必需的寻寻仔主题 Logo：按关联技能生成或复用，独立为 `品牌Logo_<中文主题>` 层，标记 `role=brand_logo`；原稿其他商标、字标整体作为图像保留。
5. 视觉大标题。
6. 图标、徽章、邮票。
7. 照片内容、相框、胶带三类元素必须分别成层。
8. 装饰插画、光效。
9. 副标题、正文、日期、说明、标签和便签文字：按逻辑块或原始行分别成层。

判断原则：

- 有独立移动价值的元素尽量单独成层。
- 同构阵列、对称组件、规律重复列表作为一个整体元素。
- 难以稳定拆开的微小装饰并入背景或最近的主体层。
- 不为追求图层数量重复拆同一元素。

### 照片版式专用拆层规则

带相框和胶带的照片版式必须严格拆成三类图层：

- `照片_具体内容`：只保留照片画面，不含相框、白边、投影或胶带。
- `相框_对应照片`：只保留相框、白边及与相框不可分割的投影，不含照片画面或胶带。
- `胶带_位置`：每一片可独立移动的胶带单独成层；四角胶带应建立四个图层。
- 照片、相框、胶带不得互相合层；不同位置的胶带也不得互相合层。

推荐命名：`照片_左侧合影`、`相框_左侧合影`、`胶带_左上`、`胶带_左下`。图层顺序按真实遮挡关系排列，通常为背景、照片、相框、胶带。

### 全文字图像层原则

视觉还原优先，不再追求文字可编辑。所有文字都必须成为独立图像层：

- 大标题：按完整视觉组合成一层，保留书法、毛笔、手绘、艺术字、定制字形、飞白、纹理和效果。
- 副标题：一行或一个完整短语一层。
- 正文：原则上每一行一层；只有原图中不可分割的多行艺术排版才合并为一个逻辑块。
- 日期、地点、署名、说明、标签：各自独立成层。
- Logo、商标和字标内部文字跟随 Logo 整体层，不再重复拆字。

双行艺术纸签需要整体移动时，可以在拆分清单中明确为一个逻辑块，例如 `文字图像_地点纸签_衢山岛`。`semantic_text` 用换行分别记录标题和说明；这类纸签属于复合组件，不能冒充单独的标题或正文素材。普通标题、副标题和正文仍按上述规则独立成层。

图层命名：

- `文字图像_大标题_具体内容`
- `文字图像_副标题_具体内容`
- `文字图像_正文01_具体内容`
- `文字图像_日期_具体内容`
- `文字图像_说明_具体内容`

每个文字图像层在 manifest 中必须包含 `semantic_text` 和 `editable: false`。这里的“不编辑”仅指不能直接改字；图层仍可独立移动、缩放、旋转、调色、加蒙版和替换。

### 2. 背景层提示词要求

背景层不是白底隔离图。提示词必须要求：

- 保持原画布尺寸、构图、光影、透视和主要纹理。
- 清除全部已计划独立成层的文字和视觉元素。
- 清除已计划独立成层的视觉元素，并自然补全其后方背景。
- 不裁切、不缩放、不新增内容。

### 3. 隔离元素提示词与透明背景

除主题 Logo 遵循关联技能的基础 Logo 与主题图参考要求外，每个独立元素都必须以原图为唯一参考调用 `image_gen`，并明确：

- “高输入保真原位隔离编辑”。
- 只保留一个目标元素或一个目标文字块；Logo 内文字随 Logo 保留。
- 隔离照片时排除相框和胶带；隔离相框时排除照片画面和胶带；隔离胶带时排除照片、相框及其他胶带。
- 隔离任何文字时必须完整保留原始字形、笔触、抗锯齿、颜色、字距、行距、方向、描边、阴影和纹理，不重新排字或替换字体。
- 保持目标的绝对位置、占位范围、视觉中心、比例、透视、方向和朝向。
- 移除目标以外全部内容。
- 独立元素默认使用 `transparent_background: true`，其余画布为真实透明 alpha；白色实体细节保持不透明。
- 白色航线、羽毛、细线、风车、桅杆、罗盘和闭合镂空图案必须优先真实透明源图。不能指望白底透明化分辨白色主体与负空间。
- 工具返回普通深色实心元素的白底隔离图时可以沿用边缘连通去白；用户明确要求白底时才主动采用纯白 `#FFFFFF`。
- 输出完整同纵横比画布，不裁成小图。模型输出像素数低于原图时由阶段 2 统一；不得把纵横比不同的图强行拉伸。

推荐提示词骨架：

```text
高输入保真原位隔离编辑。保持参考图完整画布尺寸和纵横比。
只保留【目标元素】，包括【必须保留的内部细节】；保持其绝对位置、大小、方向、透视和视觉中心。
除目标元素外，所有区域为真正透明 alpha。目标的白色实体细节保留不透明白色，内部镂空与元素间空隙也必须透明。
不得保留【易混入的相邻元素】。不裁切，输出整张同尺寸画布。
```

### 生成结果落盘

- 每次生成只调用一次，先确认结果落盘，再继续生成下一层。不要因为返回格式不同而重复生成相同背景。
- 若返回 `image_url`/data URL，使用 `generatedImage(result)` 展示结果并获取工具给出的本地保存路径；已有文件路径则直接沿用。保留工具原始文件。
- 禁止打印完整 base64，禁止把 base64 拼进 shell 参数，也不创建分块 `.b64` 文件；这会触发参数长度限制并制造重复素材。
- 从本次工具给出的目录盘点全部生成图，记录生成 ID、目标层和“选用／候选／失败”状态。不得把其他任务的图片算入本批次。

### 4. 阶段 1 检查

逐张检查：

- 背景层是否完整、无独立文字残影、无明显补全破绽。
- 元素图是否只有单一目标元素。
- 隔离图背景是否真正透明，或符合白底例外。
- 画布比例与原图误差不超过约 2%–4%。
- 对照原图目标占位框检查元素位置与大小，不能只看整张画布或缩略联系表。干净的单目标图存在整体缩放或平移时可在阶段 2 等比校准；组内相对位置、方向或字形错误必须重生成。
- 是否出现漂移、缩放、镜像、错误朝向、混层或明显重绘。
- 照片内容、对应相框、每片胶带是否分别成层，且三类元素之间不存在混层。

主题 Logo 不适用下文自动重试规则，同一用户请求最多生成一次；失败按关联技能报告，不能无 Logo 交付。其他每个失败目标默认最多额外重试 2 次，每次先说明具体错误并收紧该目标的提示词。只重做缺失或错误的目标，不重复生成通过素材。文字图生成后立即与 `expected_text` 核对，不要到合成时才发现误字。重试仍失败时保存已有生成源图并报告该目标未通过，不得交付为成功 PSD。用户随后明确要求“只重生成错误字段并继续”时，继续该目标的新一轮修正，不机械沿用上一轮停止状态。

### 5. 中断续作与已有素材复用

同一重建任务中断、重试或用户明确要求“使用现有素材继续”时：

- 先盘点本次任务已经由 `image_gen` 生成的源图；通过单目标、位置、文字语义检查的源图直接复用，不重复生成。
- 只重新生成缺失、错字、混层或位置明显漂移的目标层；不得因为单个图层失败而重做已通过的背景、照片或其他文字层。
- `image_gen` 可能返回带真实透明通道的 PNG。透明区在预览中可能显示为黑色，这不是黑底素材；阶段 2 必须保留原 alpha，不得先转 RGB。
- 同一任务先前生成但尚未归档的源图仍属于“已有素材”；完成前统一归档并补齐索引。
- 旧 PSD 或旧扁平 PNG 仍不得通过本地抠图冒充分层源图；复用仅限阶段 1 已生成的隔离源图和素材库中的合规单元素源图。

## 阶段 2：透明化、语义校验与 manifest

### 1. 使用准备脚本

复制本技能的 `scripts/prepare_assets.py` 到临时目录之外不是必须的，直接执行即可：

```bash
python3 /绝对路径/图片分层PSD重建/scripts/prepare_assets.py \
  --job /tmp/psd_rebuild_x/job.json \
  --manifest /tmp/psd_rebuild_x/manifest.json
```

`job.json` 是 Python 的输入配置，允许包含真实 Unicode；它不是最终 Bridge。其最小结构见后文。

脚本不会调用 OCR 引擎。先用现有 OCR 工具读取原图与文字素材，再把已人工复核的结果写入 `expected_text`、`ocr_text`；OCR 自身误读而图像正确时，可另写 `ocr_reviewed_text` 并记录复核依据。禁止仅填写 `semantic_text` 就声称完成 OCR。

### 2. 白底透明化规则

主题 Logo 必须直接使用真实透明 PNG；禁止白底去白、本地抠图或裁原稿代替关联技能生成。`品牌Logo_` 层使用 `box` 和 `alpha > 4` 有效边界等比定位，默认比例容差 15%，并置于其他图层上方。以下白底例外仅适用于普通元素。

脚本只删除“与画布边缘连通的近纯白区域”：

- 输入 PNG 已有真实透明通道时，脚本直接保留该 alpha；不得 `.convert("RGB")` 导致透明区变黑。
- 输入为不透明白底图时，才执行边缘连通白底透明化。
- 该方法会保留被线条围住的白色区域，也可能删除与外部白底相连的白色主体。风车之间出现白块、罗盘变白盘或海鸥失去白羽时，只重生成对应的真实透明素材，配置 `require_source_alpha: true`；不得用本地选区、遮罩或覆盖色块补救。

- 主体内部白色、浅色纸张、白色衣服、蒸汽、烟雾和高光必须保留。
- 不得按全图颜色键简单删除全部白色。
- 透明化后大部分画布必须为 `alpha=0`；否则视为隔离图失败。
- 检查主体是否被掏空、发灰、出现透明洞、白边或污染。
- 白底例外仅允许调整 `white_threshold`；白色主体或镂空仍有损失时重新生成真实透明素材，不得用本地遮罩重新拆元素。
- 对容易混入相框的短文字，可在该层配置 `max_opaque_ratio`（常用 `0.03`–`0.08`）；超限即判定混层，只重做该层。

### 3. OCR 仅用于语义校验和命名

OCR 不用于重新排字，也不用于创建 Type Layer。它只负责确认每个文字图像层的真实内容，并写入 `semantic_text`。

必须人工复核 OCR。发现以下任一情况立即停止：

- `?`、`�`、方框、乱码、mojibake。
- 缺字、错字、繁简错误。
- 行被错误合并或拆分。
- `semantic_text` 与隔离图中的实际文字不一致。

此处“停止”指该错误层不得进入合成；可以继续盘点通过素材并重生成错误字段。`expected_text` 必须保持原图内容，不能改成生成图中的错字来让检查通过。缩小后的合成图 OCR 误读时，应放大原始文字素材人工核对，不把 OCR 的误读自动当作真实错字。

### 原位几何校准与合成预览

- 对已经干净隔离、文字正确的单元素或完整逻辑块，可以配置 `target_bbox: [left, top, right, bottom]`。脚本仅裁去该生成素材的透明留白、等比缩放并平移到原图占位框，不使用原图像素。
- 不能用 `target_bbox` 隐藏混层、修正错字、镜像或改变组内关系。组内漂移应重新生成对应目标。
- `prepare_assets.py` 会输出 `manifest.preview.png`。调用 Photoshop 前必须实看此预览并与原图对照，检查纸签被放大、遮挡其他元素、船帆误添、漏字、白块、白边、元素数量与航线颜色。
- 透明 PNG 预览出现黑色时先看真实 alpha；不得先转 RGB。

### 4. job.json 示例

```json
{
  "canvas": {"width": 1024, "height": 1536, "resolution": 300},
  "white_threshold": 246,
  "assets_dir": "/tmp/psd_rebuild_x/assets",
  "layers": [
    {"name": "背景", "path": "/tmp/背景生成图.png", "transparent": false},
    {"name": "主体", "path": "/tmp/主体透明图.png", "transparent": true, "require_source_alpha": true, "target_bbox": [200, 300, 800, 1200]},
    {"name": "文字图像_大标题_引言", "path": "/tmp/引言标题隔离图.png", "transparent": true, "semantic_text": "引言", "expected_text": "引言", "ocr_text": "引言", "editable": false},
    {"name": "文字图像_副标题_写给多年以后的我们", "path": "/tmp/副标题隔离图.png", "transparent": true, "semantic_text": "写给多年以后的我们", "expected_text": "写给多年以后的我们", "ocr_text": "写给多年以后的我们", "editable": false},

```

示例 Logo 的坐标和比例仅说明字段，实际根据当前页留白和素材比例确定。主题 Logo 使用紧边界素材，不适用下述完整隔离画布透明面积门槛；准备脚本自动将 Logo 放在层序顶部。

普通透明层默认要求至少 55% 画布完全透明，可用任务级 `min_transparent_ratio` 或单层同名字段调整。短说明文字建议额外设置 `max_opaque_ratio`，用于拦截“文字连同照片/相框一起生成”的混层结果。

### 5. manifest.json 最低要求

Python 输出的 UTF-8 `manifest.json` 必须包含：

- `canvas.width`、`canvas.height`、`canvas.resolution`、`canvas.colorMode`。
- 每个图像层：简体中文图层名、透明 PNG 路径、`x`、`y`、绝对宽高。
- 每个文字图像层：简体中文图层名、透明 PNG 路径、绝对坐标和尺寸、真实 Unicode `semantic_text`、`editable: false`。
- 最终 PSD 绝对路径。
- Photoshop 应用名称。
- 至少一个 `role=brand_logo`、名称以 `品牌Logo_` 开头的独立可见层，含按紧边界等比计算的实际位置与尺寸；缺失时准备和合成脚本均拒绝执行。

脚本另保留 `source_path`、原始尺寸、源 alpha 状态、OCR 对照和目标占位框，便于归档与追溯。所有图层名必须唯一。画布比例误差超过 4% 时拒绝拉伸，需要重生成源图。

## 阶段 3：Node.js 合成 PSD

使用工作区依赖提供的 Node，不临时安装 npm 包：

```bash
/绝对路径/node /绝对路径/图片分层PSD重建/scripts/compose_psd.js \
  /tmp/psd_rebuild_x/manifest.json
```

脚本行为：

- 只读取 `manifest.json`。
- 拦截缺失、隐藏的主题 Logo；保持 Logo 层在顶部、可见且图层不透明度为 100%，保存后检查实际 Logo 层数量与可见状态。
- 将 Unicode 图层名转义到临时 JSX，避免系统语言环境破坏中文。
- 通过 macOS `osascript` 调用 Photoshop。
- 图像层按 manifest 顺序导入到同尺寸文档。
- 使用 manifest 的实际坐标和宽高放置，并删除新建文档的默认空白层；禁止多出英文 `Layer 1`。
- 所有文字以普通图像层导入，不创建 Type Layer。
- 图层名称全部保持 manifest 中的简体中文。
- 以保留图层方式保存 PSD。
- 新建时拒绝覆盖已有 PSD；保存、关闭、重新打开，核对实际尺寸、DPI、图层数量、名称与顺序及 Type Layer 数量。
- 导出完整合成 PNG 和隐藏背景后的透明 PNG 到临时 `verification/`，输出实际读取的校验 JSON，不能把 manifest 的预期值直接当成验收结果。
- 恢复背景可见性和 Photoshop 原有对话框设置；保持最终 PSD 打开。

随后执行像素与透明度核对：

```bash
python3 /绝对路径/图片分层PSD重建/scripts/prepare_assets.py \
  --verify-photoshop /tmp/psd_rebuild_x/manifest.json
```

核对使用无损 PNG，不使用 JPEG。脚本比较 Photoshop 合成与准备素材的实际像素，以及前景组合 alpha；整页前景的透明面积没有固定 50% 或 55% 门槛，单层隔离校验仍使用其约定阈值。

遇到 Photoshop `-609` 连接中断时，先检查最终 PSD 是否已经保存。重新连接／启动 Photoshop 后，对已存在文件执行以下只验收模式，禁止为一次连接失败重生成整页或覆盖正式文件：

```bash
/绝对路径/node /绝对路径/图片分层PSD重建/scripts/compose_psd.js \
  /tmp/psd_rebuild_x/manifest.json --verify-only
```

图层顺序约定：`layers` 数组从底到顶。文字图像层按原画面遮挡关系放置；若文字需要被前景遮挡，应把前景拆为“后景/前景”并在 manifest 中明确顺序。

## 阶段 4：最终验收

必须用 Photoshop 实际打开最终 PSD，而不只用 `file` 命令判断。

检查：

- PSD 像素尺寸与原图完全一致。
- 分辨率与用户要求一致。
- 至少包含 1 个背景层、多个视觉元素层，以及与原图对应的独立文字图像层。
- Photoshop 中 Type Layer 数量必须为 0。
- 所有图层名为简体中文；文字层名符合 `文字图像_类型_具体内容`。
- 每个文字图像层都有正确的 `semantic_text`，且不存在重复文字层。
- 大标题、副标题、正文、日期和说明的字形、笔触、字距、颜色及效果应接近原图。
- 元素层透明区域真实存在，主体未被掏空，无明显白边。
- 每份 PSD 必须含 `品牌Logo_` 独立层，和 manifest 的 `role=brand_logo` 对应，置顶可见且 100% 图层不透明度；位置不遮挡正文、照片主体或原有印章，未越界并保持可读。仅在素材目录或隐藏层里有 Logo 不算完成。
- 新生成主题 Logo 默认无文字；用户指定已有 Logo 内的文字随原 Logo 保留，不重复建立 Type Layer。
- PSD 能保存、关闭并再次打开。

视觉误差需要如实判断。若原图文字本身存在于独立生成的背景/插画层中造成重影，必须重做对应阶段 1 图片，不得靠覆盖色块掩盖。

## 清理与交付

验收通过后，先完成素材库归档，再清理临时文件。

### 素材库归档（强制）

实际合入的主题 Logo 原始 PNG 必须复制到对应页面的 `拼贴/品牌Logo_<中文主题>.png` 并核对哈希；关联技能的 Logo 成品目录保留原文件。同主题多页复用时，每页素材库都包含自己的 Logo 源素材副本。Logo 的无效生成稿不作为合格层源素材归档，检查预览留在临时目录；普通素材的既有归档与索引规则照常执行。

1. 将本次 `image_gen` 生成的每一张原始源图复制到素材库对应分类目录，包括背景、视觉元素和文字隔离源图；不得只保留透明化后的 PNG，不得把临时目录当作唯一存档。
2. 保留图片内容，不覆盖旧文件；文件名加入生成批次或其他可追溯标识。复合元素放入“复合组件与待拆分”类，不冒充单元素。
3. 素材库根目录必须有 Markdown 说明文档。优先更新现有 `README.md` 和 `素材索引.md`，不重复新建同用途文档。
4. `README.md` 记录素材总数、各分类数量、分类整体风格与复用规则；每次新增后必须同步更新。
5. `素材索引.md` 必须逐文件列出“分类、素材文件、该素材的具体风格、原始来源/生成批次”。不得只写分类级通用描述；新素材放入分类目录后，当次任务必须立即追加对应条目。
6. 清理前核对：本次源图在素材库中全部存在，文档总数与目录实际图片数一致，且每个新文件都有索引条目。任一不符合不得清理临时目录或声称完成。

7. 沿用素材库既有章节／页面结构；同时把原始参考图和验收后的 PSD 复制到该页面 `源稿/`。图片数、生成素材数与 PSD 源文件数分别统计，例如“33 张生成素材 + 1 张原稿 PNG + 1 个 PSD”，不能把它们都称为生成素材。
8. 既有根目录与页面说明、索引应追加或针对性更新，保留其他页面记录；每个新文件注明具体内容、风格、生成 ID／批次、源页面和选用状态。未知历史素材质量标注“本次未复核”，不得虚构已验收。
9. 复制须核对 SHA-256，一致才算归档完成。用户后续指定新素材库时按同样规则复制，不再生成素材，不移动或删除原目录。

### 交付目录清理

1. 列出交付目录内容。
2. 首次生成确认本页面只有一个正式 `.psd`；保留同目录其他页面或历史 PSD。后期改动确认新版本与正式 PSD 并存，且文件名能明确区分改动范围。
3. 删除交付目录中的 PNG、JSON、JSX、日志和预览图；临时目录可直接删除。不得删除任何正式 PSD 或历史版本 PSD。
4. 成功重建默认只提供本次新 PSD 的绝对路径链接，不附带中间文件。用户明确要求错误分析、素材复制或技能更新时，简短回答该请求并链接对应结果。

如果用户要求保留中间文件，应放在与交付目录分离的“工作文件”目录；没有明确要求时仍只交付 PSD。

## 常见失败与处理

维护脚本后运行 `python3 scripts/prepare_assets.py --self-test` 与工作区 Node 的 `scripts/compose_psd.js --self-test`，另以 `node --check` 检查 JavaScript 语法。这些自检不替代真实任务的 Photoshop 实开验收。

- `image_gen` 把相邻元素一起保留：在重试提示词中写明目标坐标范围，并点名必须删除的相邻元素。
- 透明 PNG 在预览中显示黑底：先检查 alpha；真实透明源图直接交给新版 `prepare_assets.py`，不要转 RGB 或重新生成。
- 单个文字层混入照片/相框：保留其他已通过素材，仅重试该文字层，并为短文字设置 `max_opaque_ratio`。
- 背景层清除元素后纹理失真：减少拆分数量，把难拆细节并回背景。
- 白色主体被透明化或闭合空隙变白：改用真实透明源图；不能靠阈值调整推断白色区域的语义。
- 白边明显：降低 `white_threshold`，不要全局去白。
- 文字视觉差距明显：重新原位隔离该文字块，不得用普通字体近似替代。
- 中文错字或繁简变化：核对原图 `expected_text`，只重生成该目标；先放大复核，再判断是 OCR 误读还是生成误绘。
- 元素纸签被放大、移位：查看无损合成预览，干净隔离图用 `target_bbox` 等比校准；组内关系错误则重生成。
- 中文乱码：检查 job/manifest 为 UTF-8；不要把中文正文塞入 shell 参数。
- 返回 data URL／参数过长：使用 `generatedImage(result)` 获取本地源图路径，不做 base64 shell 拼接或重复生成。
- Photoshop 未安装或 AppleScript 不可用：停止并说明无法执行最终 PSD 合成，不要交付伪 PSD。
- 发现任何 Type Layer：验收失败，删除后改为对应的文字图像层。

## 完成标准

只有同时满足以下条件才能说“完成”：

- 阶段 1 使用内置 `image_gen` 生成过背景及独立隔离素材，白色细节与闭合负空间通过真实 alpha 保留。
- Python 生成了通过 Unicode 和 alpha 校验的 manifest。
- Node 读取 manifest，并由 Photoshop 保存 PSD。
- 每份成品具有合适位置的独立可见主题 Logo；关联技能验收、实际图层数量/可见状态和 Logo 素材归档哈希检查通过，遗漏、隐藏、被遮挡或只交付独立 PNG 均不能声称完成。
- Photoshop 实开校验通过。
- 所有 `image_gen` 原始源图已归档到素材库的对应分类。
- 原始参考图与验收后 PSD 已按项目既有结构复制到页面源稿目录，副本内容哈希一致。
- 素材库根目录 Markdown 说明已同步，数量与实际文件一致，每个新素材都有具体风格和来源记录。
- 本页面首次生成只有一个正式 PSD；共享目录内其他页面保持完整。后期局部改动产生独立命名的新版本，正式 PSD 未被替换、覆盖或删除。
