# UI 对齐审计清单

## 基本判断

每次对比至少回答：

1. 参考端的页面主对象是什么。
2. 目标端是否把同一个对象放在同等层级。
3. iOS 是否是卡片摘要、表单、列表、任务中心、详情页或半模态。
4. 目标端是否使用了同样的页面类型。
5. 目标端缺的是功能模块、控件形态，还是视觉打磨。

## 导航栏

检查点：

- 返回按钮形态：圆形图标、文字返回、系统箭头是否和 iOS 一致。
- 标题内容：是否是页面类型，还是业务主对象。处方详情类页面通常应展示医院名/处方对象。
- 右侧操作：更多、归档记录、药箱、管理等是否存在，是否有图标和容器。
- 导航栏背景：白色、透明、淡灰、分隔线是否一致。

常见问题：

- 把 iOS 的对象标题改成泛化标题。
- 右侧入口从胶囊图标按钮降级成文字按钮。
- 顶部同时存在导航提交按钮和底部提交按钮，动作重复。

## 页面主内容

检查点：

- 页面是否按 iOS 的任务顺序组织，而不是字段堆叠。
- iOS 的核心信息卡是否被拆碎成多个字段块。
- 卡片之间是否有一致边距、圆角和分隔线。
- 第二张卡片是否被底部操作栏遮挡。

常见问题：

- iOS 是大摘要卡，目标端拆成多个白色小卡。
- iOS 是完整分组卡，目标端直接裸列字段。
- 页面底部 padding 不够，内容被浮层压住。

## 表单控件

检查点：

- 日期：是否为日期选择语义，选中态和回填是否清楚。
- 输入框：label 是否在输入框上方；placeholder 不应代替 label。
- 选择器：药品类型、剂型、分类、单位、状态是否有下拉语义和箭头。
- 分段控制：状态 tab 是否完整展示所有选项。
- 开关：设置有效期等是否为标准设置行。

常见问题：

- 把选择器做成普通输入框。
- 把分段 tab 做成单个孤立标题。
- 把 iOS 的下拉选择行做成胶囊标签组。

## 卡片与列表

检查点：

- 主卡片是否承载完整业务对象。
- 列表项是否有图像、标题、副信息、状态、计数和提醒。
- 药品行是否用浅灰 cell，而不是裸列表。
- 诊断、附件、关联病例是否是独立业务模块。

常见问题：

- 药品图标随机化，例如心形、星星、勾、盒子混用。
- 状态胶囊颜色与语义不一致。
- 用药数量、提醒状态、完成计数缺失。

## 图标语义

建议：

- 医院/机构：建筑、医院、处方来源图标。
- 处方：文档、处方单。
- 诊断：听诊器或医疗诊断图标。
- 附件：回形针。
- 药品：药丸、医疗包、真实药品照片。
- 提醒：铃铛或静音铃铛。
- 拍摄：相机。

避免：

- 用装饰图标替代医疗语义。
- 同一页面混用线性、填充、渐变、照片和随机图标。
- 用时钟/进度图标表达提醒。

## 优先级判断

P0：iOS 有核心模块，目标端没有。

P1：目标端控件语义错误，用户会误解。

P2：颜色职责错误，导致状态误读。

P3：视觉层级、间距、圆角、字体不一致。

P4：图标细节、动效、阴影、空态插图。
