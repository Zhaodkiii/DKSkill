# 城市旅行手账创作

**先核验内容和照片，再设计；先测量实际底板，再排字合成；每主题单独验收。** 不用生成照片补素材缺口，不把素材引用次数当独立来源数，不把本地像素一致性当事实核验。

载体默认是皮面活页本、撕边纸、金属活页环、相纸、票根、印章与胶带；皮色、纸色、城市场景随真实主题选定，不固定为棕色牛皮纸。背景必须丰富且贴近城市与故事，正文保持连续留白，真实照片是右页视觉重点。每个城市先从实拍与故事提炼自己的风格；同城不同主题可以有相应天气、时间与材质变化。禁止把上海深绿皮面、梧桐、洋房、红邮戳和咖啡组合当成全城市默认。

纪实模式只写有记录的人物、事件、变化与结果；攻略模式写有来源的路线、看点与提醒。多位作者的独立经历分别署名，不拼成用户的一次旅行，不编造动作、对话或心理。用户只说城市时默认“有来源的记录＋观看照片后的编辑感受”，不默认攻略。没有用户自己的旅行记录时，作者摘记明确署名，感受明确为编辑文字，不冒充用户亲历。只有用户明确要求攻略时才采用攻略配额。

**通用整套标准：单页2185×3130px、300dpi、约18.5×26.5cm；两张竖页组成跨页，外围为皮面活页本。每张相纸只用3/4/5寸，可任意混搭；照片自然错落、撕边与胶带融入主题，不排固定网格。右页景色贯穿照片之间，只有文字可用局部浅色底纸；照片背后不能铺大片纯色纸。每主题一个文件夹，只交付完整有字有照片的成品。**

执行前读 [整套成品标准](references/整套成品标准.md) 与 [城市风格提炼流程](references/城市风格提炼流程.md)。固定的是制版、真实素材、自然拼贴、来源与验收方法；城市的色彩、材质、场景、字体、装饰与布局必须从本次真实内容重新确定。上海图仅作为可选历史案例，不要求其他城市打开、照搬或匹配它。

## 1. 标准流程与产物

```text
确定目录与审计旧稿
  → 主题、来源集合与复用方式
  → IAB操作预检：一篇详情读取、原始记录、第一张下载与落盘验证
  → 每主题补齐10篇有效笔记，登记内容与照片价值
  → 下载技能：全部正文图片下载／已有归档核验复用
  → 路径与技术核验 → 全图视觉检查 → 每主题8张候选，最终图按故事选2–4张
  → 事实与时效核验、正文定稿、字体样张
  → 锁定物理尺寸与照片尺寸组合 → 城市与主题风格提炼 → 城市场景/贴纸设计 → 内部场景层与文字净空测量
  → 文字试排与照片机械嵌入 → 文件／事实／文字／视觉／像素验收
  → 统一封面 → 每主题独立PNG、实际尺寸打印PDF、来源与验收记录
```

| 阶段 | 必须留下的结果 | 下一阶段的条件 |
| --- | --- | --- |
| 审计与规划 | `制作记录.md`、`素材需求表.md` | 目录确定，旧稿保留策略明确，每主题边界与复用方式明确 |
| 搜索与读取 | 每篇完整URL、noteId、作者、正文摘要、页面N、读取日期 | 每主题10个有效noteId，内容与构图互补，缺口没有隐瞒 |
| 下载与复用 | 原始JSON、历史/本次浏览器记录、来源、明确采用的下载报告 | 每篇完整、无失败，实际文件路径可读，不靠报告标志代替核验 |
| 技术与视觉 | `照片验收.md`逐文件记录、每主题候选与最终选图 | 每主题至少8张合格候选，最终图单独打开，主体与水印可完整保留 |
| 定稿与设计 | 本主题 `记录与感受.md`、事实依据、字体样张、场景设计 | 文案不猜数字/门牌/日期，字体与正文可用，不串作者经历 |
| 场景与试排 | 内部场景层、`制版记录.json`实际坐标与尺寸 | 两张竖页与相纸尺寸锁定；右页无大片纯色底纸；文字仅占局部净空 |
| 合成与验收 | 正式PNG、最小可运行合成检查、`制作记录.md`验收结果 | 标题/文件/来源一致，照片像素与登记的处理结果一致，打开成品复核通过 |

任一条件失败回到对应阶段。记录“完成、缺口、下一步”，不把尝试、脚本成功或图片已保存写成整套完成。完整问题复盘与处理依据见 [流程优化复盘](references/流程优化复盘.md)。

## 2. 输入、目录与旧稿审计

输入：城市；可选主题、景点、路线、内容类型、链接、自有照片、旧稿、印刷尺寸与输出目录。合理默认先记录后执行，不反复询问可自行判断的目录与普通下载。

输出目录优先用户指定；否则已有城市目录就用其 `初稿/`。工作区末级已经是城市名时使用 `<workspace>/初稿/`，避免 `<城市>/<城市>/初稿/`；工作区不是城市目录时才创建 `<workspace>/<城市>/初稿/`。

```text
<输出目录>/
  封面/封面.png                  # 全套只做一张；已有合格封面可直接复用
  制作记录.md                    # 全套规划、来源并集计数、恢复进度
  素材需求表.md
  合成.py                        # 复用已有工具，不搭新框架
  <主题>/
    <主题>-双页.png               # 完整内容＋外围皮面活页本
    <主题>-双页打印.pdf           # 两张完整单页，按实际尺寸打印
    记录与感受.md
    来源.md                      # 作者、正文依据、选图、权威归档路径
    照片验收.md
    制版记录.json                # 单页/整图/相纸尺寸、坐标、hash、旋转
    验收.md
    照片/<noteId>-01.webp         # 本主题最终选图，不修改原文件
    贴纸/                        # 仅归档实际用到的独立装饰素材
  素材归档/                      # 已有权威归档可原位引用，避免重复复制
    <来源组>/来源.md
    <来源组>/原始记录/<noteId>.json
    <来源组>/<noteId>-下载报告.json
    <来源组>/<noteId>-01.webp
```

每主题的成品、正文、选图与来源必须在同一主题文件夹。内部场景层、文字样张、掩码与预览可在工作目录使用，不能把它们当额外“无照片版/无字版”交付，也不为交付再生成这些变体。既有历史底板保留原位，不删除历史文件。用户要求修订时默认新建 `修订版/`，保留 `初稿/`；不得仅通过改文件名掩盖内容串页。最终脚本使用持久素材路径，不能依赖 `/tmp` 中可能消失的文件。

仅创建正在处理的目录，不建空的未来主题。复用模式的真实路径说明见第3节；上述照片结构适用于本主题独立归档。

审计动作：

1. 列出已有封面、双页、照片、来源和报告；记录它们的真实路径。
2. 打开已有成品，对照标题、内容、文件名，查错城、串页、空泛内容、照片主体与城市背景。
3. 查原始素材、最终选图与机械合成记录。**仅凭画面不能判定是真实照片或模型照片**；没有记录时标“来源/合成未核实”，不先定性。
4. 优先核验可复用原素材。需要替换时在原主题目录保留旧版为 `<主题>-双页-旧版.png` 或 `封面-旧版.png`；该名称已存在则加本次时间，不覆盖旧备份。原文件无需替换时保留原位并标明本次正式文件。

## 3. 主题规划、来源集合与复用规则

默认规划2–4个叙事明确的主题；用户指定数量优先。各主题写明核心、景点边界、所需事实、照片角色、季节/天气和最终图的分工；通常3–4张，用户允许的两图组合也可使用。不能为了凑数量把同一页换标题重复交付。

**每主题仍须有10篇不同noteId的有效图文笔记。** 独立集合优先；相邻主题可以交叉引用相关笔记，但须在下载/生成前登记：

- 此篇对每个主题的具体内容或照片贡献，不能只写“通用街景”。
- 本主题的10篇名单与缺口；只搜索了一个词、只复制了目录，不等于另一主题采集完成。
- 整套独立来源数按全部noteId取并集；每主题引用数分别列出。同一篇复制、复读、重试只计一篇。
- 每主题的候选与选图独立评估。跨主题最终照片默认不重复；用户明确要求重复时注明用途，不误报新增图片。

先选择一种复用方式，避免同一份报告在不同目录下含义混乱：

| 方式 | 使用条件 | 来源与路径要求 |
| --- | --- | --- |
| 原位引用（优先） | 多主题引用同篇且不需要独立打包 | 保留一份权威归档；本主题 `来源.md` 追加引用段，指向实际原始JSON、浏览器记录、报告和照片绝对路径，写相关性与本次核验时间。不能宣称照片已复制到本主题。 |
| 本主题独立归档 | 需要独立交付/打包，或用户指定统一保存目录 | 调用下载技能的 `--reuse-report`；复制原始记录并重新生成当前组报告。`files[].file` 必须指向当前组。禁止整目录复制后直接沿用报告。 |

已有合格链接可计入集合；本次在IAB核对详情身份、正文、页面N，补足不足部分。保留历史来源台账，不伪造本次下载时间。完整归档可复用，历史 Downloads 临时文件消失无需重下整篇。

`素材需求表.md` 每篇至少登记：主题、标题、作者、noteId、用户链接（如有）、完整详情URL、页面N、日期原文与读取日期、正文摘要、内容价值、照片价值、采用报告/原始记录/图片目录路径、是否复用及理由。主题末尾列本主题引用数、整套独立来源数、失败/缺口。

## 4. IAB搜索与稳定操作

**搜索、筛选、详情读取、评论、短链接解析与下载页面访问全部只用Codex内置浏览器IAB。** 不启动或读取Chrome/Safari/Edge账号、Cookie、配置；不用通用网页搜索或HTTP访问替代笔记搜索与正文读取。下载方式由依赖技能规定。

首次调用严格按 `cua_repl` 初始化文档；有相关IAB标签就复用，否则后台创建 `cua.createBrowserTab("iab", url, { visible: false })`。工具文档是当前API依据，不照搬旧控件索引或假设角色。

稳定搜索动作：

1. 读取当前AX/DOM，找到实际 `input` 或 `textarea` 搜索控件；输入主题关键词。
2. 输入后读取新状态，确认字段值。页面切换导致控件变化时重新定位。
3. **优先点击实际可见搜索按钮/图标**。回车失败时先看字段值与页面状态，不能连续对旧索引重试。
4. 检查URL与搜索结果是否对应关键词；只在确实仍在加载时做一次有目的的补充读取，不加固定长等待。
5. 从已观察到的结果点击详情，确认noteId、标题、作者、正文与 `1/N`。不猜详情URL或参数。
6. 需要返回搜索时确认导航结果。如果URL/DOM仍停在详情、或当前没有搜索控件，重新读取；无法恢复则在**同一IAB**新建后台标签，不切换外部浏览器。

关键词必须覆盖“小众”和“女生照片”，可拆分成内容/照片两类：

```text
<城市> <主题> 小众 女生照片
<城市> <景点> 小众 女生拍照 实拍
<城市> <主题> 女生旅行 游记 真实经历
<城市> <主题> 小众 一日游 攻略 路线
<城市> <景点> 女生 人像 机位 旅行日记
```

优先女生与景点同框、真实游玩场景、地标全景与现场细节；人物偏好根据关键词与作者自述，不凭外貌推断身份。拒绝重复noteId、错城、纯视频、只空泛文案及高度重复素材。笔记须为 `/explore/<id>` 或 `/discovery/item/<id>`；完整保留 `xsec_token`、`xsec_source` 等参数。短链接在IAB正常解析并登记最终URL。

搜索结果仅供筛选，不能下载缩略图；推荐流、头像和评论图片不作正文照片。未登录、验证码或访问限制时保存进度并报告具体阻挡，按工具要求交由用户在IAB处理，不绕过。

## 5. 事实、日期与正文定稿

读取详情正文及与事实相关的高价值评论。原文、事实摘录和最终文案分开保存；每条写入正文的事实指向noteId或其来源条目，图片作者与正文作者不能串配。

| 内容 | 标准处理 |
| --- | --- |
| 路线与交通 | 保留作者实际顺序、入口/出口；多条独立路线分别注明，不拼成未经验证的一日行程。 |
| 具体门牌、地标、机位 | 正文、画面与评论一致才使用；415/425号这类冲突保留冲突记录，正文降为街道名或省略精确数字。 |
| 时间、票价、营业、预约 | 记录来源日期；当前未确认就不硬编码，写出行前以官方当日信息为准。 |
| 页面仅显示“03-28” | 保存显示原文，不自行补年份；拍摄日期、发布/编辑日期、读取日期分别记录。 |
| 往年照片、季节、天气 | 不把历史秋景或晴天照片称为今天现况；叶色时间冲突时改为查看实况。不同天气分别描述，不统一冒充同一天。 |
| 纪实与作者体验 | 只写有记录的事件和结果，商业约拍宣传不作为已经发生的用户体验。 |

攻略左页至少有真实路线、2–4个具体看点、2条实用提醒；纪实围绕人物/地点、事件、变化或结果。不用“很美、值得去”填版，不凭常识补数字。精确地点无法确认的照片只标已确认范围；其叙事角色无法说明时不选。

先在 本主题 `记录与感受.md` 定稿，再排版；为了排版缩短文案时，记录模式保留事件、归属与感受，攻略模式保留路线、核心事实与提醒，不把删节变成事实改写。

## 6. 下载技能交接与归档门禁

每次执行前读取 [小红书链接图片下载](/Users/hua/Documents/Skill/小红书链接图片下载/SKILL.md)。只在该技能维护提取器、下载器和复用实现，本技能不另写替代工具。

交接明确传入：本主题10篇已登记完整链接、来自本任务的下载授权、IAB-only页面访问、照片父目录/合集、原位引用或独立归档方式、全部正文图片、原始记录与来源报告。普通下载与记录写入无需再次确认；仅分析/规划未授权下载时不执行。依赖文件缺失时保留名单并报告，不能临时另造下载器。

下载技能预检采用**完整原函数静态回调**，禁止 `return + 带注释IIFE`、`eval`、`new Function` 和临时简化提取器。返回空值与图片数不符必须先修复，不能开始合成。先跑通一篇与一张下载，再扩展本批名单。

下载后按明确采用的报告逐篇核验：

- `complete=true`、`failed=[]`，页面N=提取数=已保存位置数；每篇全部正文图片完成，不只下载3–4张拟选图。
- 原始JSON、浏览器路径记录、报告和来源条目存在，noteId、顺序和URL对应。
- 文件路径存在，解码、实际格式/尺寸与SHA-256通过；`complete=true`单独不够。
- 原位引用报告指向权威归档，独立归档报告指向当前组；历史临时下载路径仅作历史证据。
- 同noteId重试报告采用哪一个须记录，不从多个旧报告拼出虚假的完整状态。

某篇失败先登记，继续处理其余已授权笔记，再由下载技能补缺。十篇都完整后才进入选图；不足或受阻不能生成假照片。

## 7. 全图视觉验收与选图

使用本机已有Pillow/ImageMagick/Sharp，不为联系表新增依赖。正文图片是网页版本，不称作者原图；保持原文件、水印、顺序和报告，不因候选淘汰删除源素材。

技术检查：文件可解码，不是HTML；通常大于20KB，短边建议≥800px；尺寸偏小必须逐张确认。按SHA-256识别重复，但不同轮播位置字节相同时仍保留全部位置，不让下载数与页面N失配。

视觉检查：

1. 为**全部图片**生成有文件名和顺序的联系表，建议每页12–20张；标签须能读清完整noteId与序号。
2. 逐张查看并登记地点依据、主体、季节/天气、主题匹配、重复关系、保留或淘汰的**具体原因**。
3. 联系表是全图筛查，不代替细节核验。所有拟保留候选、最终图及疑似重复、地点不明、人物/水印不清的图片均单独打开。
4. 禁止对未辨明的图片批量写“主题关联弱”。可明确写“只有圣诞装置，与本页春日主题冲突”“与xx同hash”“没有可确认地标，无法作为全景”。

`照片验收.md` 表格字段：`文件/实际路径｜noteId｜地点与依据｜主体｜季节/天气｜技术结果｜重复对象｜候选/淘汰｜具体理由｜查看方式`。

每主题至少8张不同内容的合格候选，再按叙事选2–4张（通常3–4张）：人物主视觉、标志全景、人物互动/生活场景、细节/补充视角。候选宜有2–4张人物、2–3张大景、2–3张细节；博物馆、遗址、自然保护区可降低人物比例，仍须现场细节。

在本主题 `来源.md` 末尾追加“最终选图”：文件绝对路径、noteId、确认地点、作者、相纸编号/寸数、叙事角色、对应文案。原位引用时这里引用真实原目录，不能只写本主题不存在的文件名。

## 8. 字体预检、城市风格提炼与生成门禁

字体优先本机已有中文字体。生成前用标题、全部地名、作者名、箭头和实际标点做一张文字样张并打开：

- 字符出现方框/缺字时先换已安装字体或使用已有回退字体；不要假设字体能显示所有emoji。
- 装饰性emoji可以在成品署名中省略，但来源台账保留作者原名；姓名/地名实际汉字缺失不能直接删掉。
- 用字体实际测量宽度和行高，不按字符数猜排版。自动换行、正文最小字号与行距先确定；内容太多先精简或加页，不无止境缩字。

按 [城市风格提炼流程](references/城市风格提炼流程.md) 从本次实拍和故事提炼风格，不先套城市模板。`制作记录.md` 每主题必须写：旅行底色（照片的季节、天气、时间与光线）、主辅色/皮面/纸张材质、城市识别元素、故事环境、远近景层次、正文/照片/图注/中缝分工。具体地标先核外形；水彩、版画、纸艺或线描是装饰插画，不伪称准确地图或机位。

丰富背景必须在顶部、侧边或下缘有清楚可见的**城市/故事环境**，填照片后仍可见；不能只换标题，其他仍是通用纸张、花枝和胶带。海岛按真实海面/岛屿/天气，老城按河道/瓦檐/石路，街区按门窗/街道/生活物件设计，不混入其他城市或无关山海。

生成前逐主题确认：10篇有效来源及完整报告、8张候选、所有已单独查看的最终选图、事实已定稿、作者/日期没有合并、旧稿策略、字体样张、场景设计均通过。全套独立来源按并集统计。未通过不调用图片生成。

## 9. 尺寸锁定、场景层与自然拼贴设计

### 9.1 先锁定印刷尺度

单页竖版 **2185×3130px，300dpi，约18.5cm宽×26.5cm高**。用户描述“26.5×18.5cm”时，以同时给出的像素方向核对宽高，不把单张做成横版。两页内容区合计4370×3130px；载体在内容区外，不占用内容页尺寸。

推荐整图4920×3530px：左页 `[200,200,2385,3330]`，右页 `[2535,200,4720,3330]`；中央150px，外围约200px。坐标为半开矩形。此为可复用尺寸模板，只有承载位置可以依实际设计调整，两张内容页的宽高不能变。活页环位于中央载体，不穿过照片或文字。

相纸外框的唯一尺寸表（横向使用时交换宽高）：

| 相纸 | 英寸 | 厘米 | 300dpi像素 |
| --- | --- | --- | --- |
| 3寸 | 2×3 | 5.08×7.62 | 600×900 |
| 4寸 | 3×4 | 7.62×10.16 | 900×1200 |
| 5寸 | 3.5×5 | 8.89×12.7 | 1050×1500 |

**相纸尺寸包括白边与撕边，不是只规定照片内图尺寸再额外加一圈相纸。** 胶带和独立图注可以在相纸外。旋转前锁定相纸矩形；旋转后轴对齐包围框会增大，不能拿这个包围框核算寸数。不能把带外围皮面的整图缩成单页尺寸；打印时只裁出内容页，以100%实际尺寸输出。

每主题按内容选尺寸组合与横竖方向，例如“2张3寸＋1张4寸”“1张5寸＋2张3寸”“3张3寸”“1张3寸＋1张5寸”。最后一种是用户允许的两图模式；最终图数量随叙事与用户要求调整，不为配额硬塞照片。全套不固定同一组合，不把所有照片统一缩放到同一个框。自由摆放指位置、角度、组合自由，不能任意拉伸或改变相纸外框尺寸。

### 9.2 场景、纸面与贴纸

- 每主题独立设计完整双页；使用正上方视角，避免无法校准物理尺寸的透视。
- 左页正文可以有连续浅色低纹理纸面，街景在顶部、侧边和下缘可见；文字不得压枝叶。
- **右页底层是完整的城市/故事景色。照片直接贴在景色上，照片区域及照片间的留白不加统一纯色底纸、通栏牛皮纸、白色大卡片或四格底板。** 标题、短句与图注需要对比时，只在它们实际文字边界外加小幅安全留白的局部撕边纸，不扩成整页遮罩。
- 先安排叙事主图，再围绕树影、街角、桌面等背景关系摆次图。位置、间距与倾斜各自变化，可跨页分布；不固定“左文右三格”，不把轻微旋转当作已经解决了网格僵硬。
- 相纸边缘轻微不规则，白边克制，接触阴影贴近纸张；适量透明胶带、压花叶片、邮戳、咖啡或本地生活物件贴纸承担故事衔接。装饰跟随主题，不机械堆同一套符号。邮戳/票根只能是装饰，不能虚构真实日期、消费或行程。
- 允许纸边、胶带和贴纸之间有层叠；真实照片画面、人物、建筑、水印、正文与作者署名保持完整可见。每一处遮挡都要检查，不凭“手账随意”允许覆盖。
- 皮面采用连续真实皮纹与缝线，不用短条纹理平铺出重复条带；活页环、中缝、纸厚与阴影符合实体逻辑。

### 9.3 生成、复用与实际测量

优先复用已核验照片、文字与既有场景素材。使用图像生成工具生成/修正**场景、载体与装饰层**，实拍区域始终由后续机械合成填入；不得靠模型保持人物或水印。内部生成层不单独作为无字/无照片版本交付。每主题最终生成独立成品，内部批量素材可以拆分，但拆后分别测量、合成、验收。

提示词必须填入实际城市、季节/天气、场景层次、主辅色、单页/载体分工，以及“右页全幅主题景色，只有局部文字底纸，无统一照片底板、无固定网格”的要求。场景层不要生成照片框、正文、图注、伪中文和具体票据数字。独立贴纸需真实Alpha、对象分离、紧边界；不要把棋盘格或模糊背景当透明。

**不把已含照片和文字的完整稿再交给模型作为最终成品重绘。** 若曾这样尝试，必须退回清洁场景层重新合成；在模型旧照片上覆盖新照片容易残留第二张照片、双重边框、重复署名。不能只把主图覆盖后就宣称实拍验收通过。

生成返回只显示图像及路径/尺寸等短元信息，禁止打印完整返回对象或Base64。原生分辨率如实记录；放大至制版尺寸不称原生300dpi细节。生成后实际打开检查，记录当前页净空、场景、禁覆区域与真实坐标，不使用未经核对的提示词坐标，也不沿用旧稿坐标。

## 10. 机械合成、像素检查与打印

使用本机已有Pillow/Sharp/ImageMagick，不新增框架。流程为“场景/载体 → 局部文字底纸 → 固定尺寸相纸与实拍 → 胶带/独立贴纸 → 本地正文与图注 → 保存检查”。交叠顺序以不遮挡主体和水印为准。

1. 相纸外框严格按9.1表建立；白边、撕边向**内**处理。照片默认完整等比适配到相纸内图区，比例差用相纸留白吸收；每张源图可按自身比例单独适配，不强制整组用同一缩放系数。不拉伸人物，不生成式扩图。
2. 必要裁切须先查看、记录源裁切矩形，确认人物、动作、建筑名牌与原水印完整；无法同时保留就改方向、换尺寸、留白或换图。水印不得去除、覆盖或仿造。
3. 相纸、照片、纸边与胶带作为一组轻微旋转，记录旋转中心、角度、相纸原尺寸、最终位置与有效照片掩码。图注可做相纸内部小字或外部独立纸条，但不得加大相纸尺寸冒充标准寸数。
4. `制版记录.json` 至少包含：DPI、单页物理/像素尺寸、整图尺寸、两页裁切框、内部素材持久路径、原生/输出分辨率；每图源路径/noteId/hash/作者/角色、相纸寸数与外框像素、内图区、缩放/裁切、旋转、位置、照片有效掩码与图注。源文件保持原样。
5. 保存PNG后重新解码。按登记变换重新构造每张实拍图块，在其有效照片掩码内与最终图比对（旋转插值允许声明的微小误差）；源hash、图片能解码和左页像素一致都不能代替右页照片的比对。逐张人工核对人物、衣服、动作、建筑、作者、水印及所有装饰遮挡。
6. 检查旋转后的相纸、阴影和贴纸没有越页、越中缝、压正文或遮水印；根据文字实际边界检查局部纸面大小，不用大纸面修复对比度。
7. 输出 `<主题>-双页.png`，保留完整皮面载体。另按两页裁切框输出 `<主题>-双页打印.pdf`，每页2185×3130px对应约18.5×26.5cm、300dpi；检查PDF实际MediaBox宽高，而不是只核对PNG的DPI元数据。图像尺寸允许1px舍入；打印100%，禁用“适合纸张”。装订孔、出血、裁切线只有已知实物要求时再加，不自行缩小内容页。
8. 保留一个可运行检查。尺寸与hash可使用本技能 `scripts/check_print_spec.py`，字段与运行方法见 [制版记录与检查](references/制版记录与检查.md)；像素掩码核验留在实际合成脚本中，视觉验收单独记录。只报告实际执行通过的范围。

## 11. 封面与最终验收

全套只做一张正式封面，沿用皮面、颜色与场景体系；城市名是重点，配简短副标题，不堆攻略文字。可用明确的装饰插画；若使用实拍也必须登记来源并机械嵌入。封面可复用本城市已认可参考；必要的内部场景层后用本地字体排中文，仍做字体与净空检查，不额外交付无字版。贴纸工艺与本城市的封面、场景和主题统一，不把其他城市封面的配色、符号或单张大图布局套到每页。禁止错城符号。
