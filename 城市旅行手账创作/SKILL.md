# 城市旅行手账创作

本技能用于把城市旅行内容做成可追溯、可核验的收藏手账。默认载体是皮面活页本、撕边纸、金属活页环、实体照片墙、票根、印章、胶带和手写注释。皮面颜色、纸张底色与装饰材质必须跟随城市和故事选择，不固定为深棕皮面与满页牛皮纸。

**视觉原则：背景需要丰富，而且要贴近这趟旅行的底色、这个城市的特色、这个故事发生的环境。** 城市场景应成为可见的背景主体；正文保留清楚的留白，实拍照片保持视觉重点。

内容类型以用户要求为准：纪实手账写真实发生的经历，攻略手账写路线与实用信息。下文的路线、票价、提醒配额只适用于攻略模式；纪实模式用有来源的人物、事件、变化与结果替代，不强行写成攻略。

核心原则：**先有真实旅行内容与小红书详情页原图，再做设计。没有合格照片，不得生成成品。**

## 标准流程总览

执行顺序固定，不得交换或跳步：

```text
现状审计
  → 主题与素材需求表
  → 每主题读取 ≥2 篇小红书详情页
  → 原图下载 + 来源台账
  → 技术验收 + 逐张视觉验收
  → 左页内容定稿 + 右页最终选图
  → 城市与故事背景设计定稿
  → 生成“无照片底板”
  → 把小红书原图机械嵌入照片框
  → 文字、主题、照片来源三重验收
  → 交付
```

每个阶段必须留下可检查的结果：

| 阶段 | 必须产物 | 通过条件 |
| --- | --- | --- |
| 搜索 | 详情页链接 | 每主题至少 2 篇：攻略模式查攻略与实拍；纪实模式查真实经历与实拍 |
| 下载 | 原图文件、`来源.md` | 每主题至少 8 张合格候选图 |
| 选图 | `来源.md` 的“最终选图”段落 | 3–4 张，人物/地标/细节有分工 |
| 文案 | 左页故事或路线与提醒 | 每条事实可追溯，动态数字有日期 |
| 设计 | 背景设计说明、无照片底板 | 城市与故事场景丰富可见；正文可读；照片框为空，不生成假照片 |
| 合成 | 正式双页 PNG | 照片框内为下载原图像素，不是模型重绘 |
| 验收 | 打开的成品与文件清单 | 标题、内容、文件名、来源全部一致 |

任一阶段未通过就回到对应阶段修正，不能用生成模型补齐缺失证据。

## 输入

- 城市名称。
- 用户指定的主题、景点、故事或路线。
- 内容类型：真实游记／故事纪实／攻略；按用户表达选择。
- 可选：小红书链接、现有照片、旧版成品。
- 输出目录；默认 `<workspace>/<城市>/初稿`。
- 可选：人物照片偏好、印刷尺寸、是否覆盖旧稿。

## 标准目录

只创建正在处理的主题，不创建空的未来目录。

```text
<城市>/初稿/
  封面.png
  <主题>-双页.png
  <主题>-双页-旧版.png
  照片/
    <主题>/
      来源.md
      原始记录/
        <note-id>.json
      <地点>-01.webp
      <地点>-02.webp
      <地点>-下载报告.json
```

`来源.md` 是强制交付物。只有图片、没有来源记录，视为流程未完成。

在文件末尾追加最终选图，明确成品会使用哪些原图：

```markdown
## 最终选图
- `<文件名>`：人物主视觉；照片框 1
- `<文件名>`：标志性全景；照片框 2
- `<文件名>`：人物互动；照片框 3
- `<文件名>`：现场细节；照片框 4
```

## 0. 审计现状

开始新城市或接手旧稿时：

1. 列出初稿目录中的成品和照片。
2. 检查双页标题、内容、文件名是否一致。
3. 检查照片目录是否为空，是否有来源记录。
4. 打开已有成品，识别：
   - 照片是真实旅行实拍，还是模型凭空生成；
   - 是否只有大景，缺少人物、细节和实际游玩感；
   - 是否出现错城、错景点、错误标签或主题串页；
   - 攻略是否缺少路线与实用信息，纪实是否缺少具体事件与变化；
   - 背景是否缺少城市与故事场景，只剩通用纸张、花枝和胶带。
5. 重做旧稿时，先保存为 `<主题>-双页-旧版.png`，再替换正式文件。

不得因为旧稿“看起来像旅行手账”就跳过素材核验。

## 1. 主题规划

把景点整理成 2–4 个有明确叙事的主题。每个主题先写明：

- 核心故事；
- 目标景点；
- 需要的照片类型；
- 左页需要验证的真实事件或攻略信息；
- 右页预计使用的 3–4 张照片。

示例：

- 皇城中轴线：永定门、天安门、故宫、景山、钟鼓楼。
- 园林山水：颐和园、圆明园、北海公园、香山。
- 胡同人文：南锣鼓巷、什刹海、烟袋斜街、国子监。

### 1.1 城市与故事背景设计（必做）

生成前在输出目录的 `制作记录.md` 写明以下内容，已有制作记录就直接补充：

- **旅行底色**：从已核验照片和正文提取实际环境、季节、天气、时间与旅行节奏；选定主色、辅助色和材质。晴海、阴天、夜航、雪路应有各自的色彩与光线。
- **城市特色**：选择有依据的地形、建筑、植被、生活物件与地方纹理，明确哪些元素能让人认出这里。具体地标先核实外形；抽象装饰不标成准确地理图或真实机位。
- **故事背景**：提取这件事发生的环境与物件，例如出海的海面与绳结、老街相遇的门窗与路面、雪中行走的山线与脚印。不同故事要有不同的场景重点。
- **丰富背景的构成**：远景环境、近景场景、实体手账材质分层安排。城市风景或生活场景必须占据清楚可见的背景区域；小物和票根承担故事补充。
- **版面分工**：写明场景背景、正文留白、照片框与图注的位置。照片填入以后，背景仍应看得出城市与故事；正文与图注仍应清楚可读。

方向示例（按实际主题使用，不机械套用）：

| 城市／旅行主题 | 旅行底色 | 丰富背景的场景来源 |
| --- | --- | --- |
| 舟山海岛、看海与出海 | 海蓝、海玻璃绿、云白、沙色 | 岛屿层次、海面、天空、岩岸、已核实外形的灯塔；绳结、贝壳、渔网作为近景细节 |
| 江南老城、雨中散步 | 青灰、湿润绿、米白 | 河道、石桥、瓦檐、湿石板、窗格；雨天用柔灰光线 |
| 雪山徒步、山村停留 | 雪白、岩灰、林绿与少量暖色 | 山线、森林、步道、山村；天气和植被按照片核实 |
| 城市街巷、茶馆或市场故事 | 从真实街景与店内光线取色 | 对应街巷、门窗、桌面、招牌形态与生活物件，避免硬塞山海背景 |

**禁止通用背景直接交付**：不能只换城市标题，其他仍是大面积空牛皮纸、通用花枝和胶带；不能把城市特色缩成角落一个小印章。丰富来自场景、材质和叙事层次，装饰不得遮挡正文或照片主体。

背景中的水彩、版画、纸艺或线描是装饰插画，必须与嵌入的真实照片区分。不得生成假照片、伪造游客经历或加入未核实的具体地标。纪实正文不编造对话、心理独白或未记录的动作；多位作者的独立经历应分别署名，不合并成同一次旅行。

## 2. 搜索小红书旅行内容

没有用户链接时，必须在小红书搜索。每个主题至少读取 2 篇有效笔记：

1. 一篇内容型笔记：攻略模式要求实用信息明确；纪实模式要求有具体人物、现场事件、变化或结果。
2. 一篇实拍型笔记：图片充足，包含人物、地标、环境或细节；可同时提供另一段有来源的真实经历。

推荐搜索词：

```text
<城市> <景点> 游记 旅行日记 真实经历
<城市> <故事关键词> 实拍 记录
<城市> <主题> <景点1> <景点2> 一日游 攻略 路线
<城市> <景点> 拍照 人像 出片 机位
<城市> <景点> 细节 实拍 游玩体验
```

标准搜索动作：

1. 按内容类型搜索：攻略模式搜“路线 / 一日游 / 避坑”；纪实模式搜“游记 / 日记 / 真实经历 / 具体事件”，找到支撑左页正文的笔记。
2. 再搜“拍照 / 人像 / 机位 / 实拍”，找到支撑右页照片墙的图文笔记。
3. 搜索结果只用于筛选；必须点击进入详情页。
4. 确认最终 URL 包含 `/explore/<note-id>`，并等待 `.note-container` 加载完成。
5. 记录标题、作者、详情页 URL、攻略价值、照片价值和淘汰原因。
6. 选择内容与构图互补的笔记，避免两篇素材高度重复。

短链接 `xhslink.cn` 必须先在浏览器打开并解析到最终详情页；`来源.md` 记录最终详情页 URL，用户提供的短链接可留作备注。

优先选择：

- 能覆盖多个目标景点的路线攻略；
- 有明确交通、耗时、入口、预约或避坑信息；
- 图文笔记，而非只有封面的纯视频；
- 详情页图片数量足够且能识别地点；
- 人物与景点同框、真实游玩状态明显的笔记。

禁止：

- 把搜索结果页缩略图当正文图片；
- 只看标题，不打开详情页；
- 只读一篇纯视频笔记便开始创作；
- 使用推荐流、评论区或其他城市图片。

## 3. 读取真实游玩内容

读取正文和高价值评论，只记录页面实际出现的信息：

- 游玩顺序与入口、出口；
- 交通方式与大致耗时；
- 建议游玩时长和体力要求；
- 核心体验、机位和停留点；
- 预约、放票、开放时间、票价；
- 拥挤、天气、楼梯、步行和返程避坑；
- 被多名游客验证的评论补充。

规则：

- 不用常识补齐具体数字。
- 信息冲突时写“以官方当日信息为准”。
- 时效性强的信息注明来源日期或改成非硬编码提示。
- 攻略左页至少包含真实路线、2–4 个核心看点、2 条实用提醒；纪实左页围绕“人物与地点 → 发生的事 → 变化或结果”展开。
- 不以“很美、值得去、氛围很好”一类空话作为主体内容。

攻略笔记按以下结构提炼；纪实笔记另记人物、地点、时间、真实事件、转折／结果与对应原图，缺失信息不补编：

```text
路线：入口、游览顺序、出口
时间：作者实际建议或实际花费
看点：具体建筑、展品、机位、活动或体验
人物拍摄：站位、背景、光线、拥挤情况
避坑：预约、排队、步行、天气、返程、临时关闭
时效信息：笔记日期 + “出行前以官方当日信息为准”
```

正文与图片必须来自同一详情页，不能把 A 笔记的文案记到 B 笔记的图片来源下。

## 4. 建立来源记录

下载前创建 `<主题>/来源.md`。每篇笔记记录：

```markdown
# <城市>｜<主题> 照片来源

## 笔记 1
- 标题：
- 作者：
- 详情页链接：
- 笔记日期：
- 读取日期：
- 用途：攻略 / 人物实拍 / 地标 / 细节
- 已验证内容：
- 原始记录：原始记录/<note-id>.json
- 下载报告：<地点>-下载报告.json

- 备注：仅用于个人旅行手账参考，不移除水印
```

必须记录打开后的详情页链接，不能记录搜索结果页链接。

## 5. 从详情页解析并下载原图

本技能自带两个通用脚本：

- `scripts/xhs_extract.js`：在详情页上下文提取标题、作者、正文、note ID、图片尺寸和图片 URL。
- `scripts/download_xhs_images.py`：下载、重试、识别真实格式、按内容去重，并生成失败清单和 SHA-256 台账。

### 5.1 提取详情页

等待轮播图和正文加载完成后，在当前页面上下文执行完整的 `scripts/xhs_extract.js`。脚本会：

- 只读取 `.note-container`；
- 同时检查 `currentSrc`、`src`、`srcset`、`data-src`、`data-original`；
- 排除评论、头像、表情和小尺寸图片；
- 保留页面顺序、图片尺寸、正文、作者和详情页 URL；
- 对 URL 去重。

把返回对象原样保存到 `<主题>/原始记录/<note-id>.json`。若 `images` 为空，确认当前页是图文详情页并滚动轮播完成加载；仍为空则更换图文笔记，不得退回搜索结果缩略图。

不方便执行通用脚本时，才使用下面的最小降级代码：

```js
const urls = [...new Set(
  [...document.querySelectorAll('.note-container img')]
    .map((img) => img.currentSrc || img.src)
    .filter((src) =>
      src.includes('sns-webpic-qc.xhscdn.com') &&
      !src.includes('/comment/')
    )
)];
```

### 5.2 下载与自动校验

在 Skill 目录执行：

```bash
python3 scripts/download_xhs_images.py \
  '<主题>/原始记录/<note-id>.json' \
  '<主题>' \
  --prefix '<地点-A>'
```

下载第二篇笔记时使用不同前缀，或用 `--start` 指定后续序号。只有明确需要替换同名文件时才使用 `--overwrite`。

下载器默认：

- 使用浏览器 User-Agent、图片 Accept 和详情页 Referer；
- 每张图最多尝试 3 次，单次超时 30 秒；
- 小于 20 KB 的响应判为可疑；
- 根据文件魔数识别 JPEG、PNG、GIF、TIFF、WebP、AVIF，不相信 URL 后缀；
- 拒绝 HTML 错误页；
- URL 去重后再按 SHA-256 做内容去重；
- 先写 `.part` 临时文件，成功后原子替换；
- 输出 `<前缀>-下载报告.json`，记录失败原因、字节数和 SHA-256。

首次使用或脚本修改后运行：

```bash
python3 scripts/download_xhs_images.py --self-test
```

退出码为 `1` 或下载报告中的 `failed` 非空时，不得进入选图阶段。若出现 403 或签名失效，重新打开原笔记并重新提取 URL，不要反复请求旧链接。

下载规则：

- 使用解析出的原图 URL，不截搜索页缩略图。
- 文件名使用地点与序号，如 `故宫-01.webp`。
- 同一 URL 去重。
- 保留原内容与水印，不冒充原创。
- 纯视频只能取得封面时，标记“视频封面”。
- URL 失效时重新打开详情页解析，不用无关网络图补位。
- 一篇笔记使用一个独立 JSON 记录和独立文件名前缀，避免多篇笔记序号互相覆盖。
- 下载报告中的 URL、文件名和 SHA-256 属于来源台账，不得只留下无法追溯的散图。

排除：

- 推荐流、评论区、头像和表情；
- 广告、二维码、网页截图；
- 其他城市、其他景点；
- 与主题无关的食物或室内画面。

人物照片不是默认排除项。人物与目标景点明确同框、能体现真实游玩体验时，应优先保留。

## 6. 下载后技术验收

不能以“下载命令成功”作为完成标准。逐文件检查：

1. 文件存在且通常大于 20 KB；过小文件人工确认。
2. `file` 能识别为图片，不是 HTML 错误页。
3. 图片可打开，长宽合理，建议短边不低于 800 px。
4. 下载报告 `failed` 为空，且文件数量与来源记录一致。
5. 用下载报告中的 SHA-256 排除跨笔记重复图。
6. 每张候选图都做视觉检查，不能只抽查前几张。

错误文件直接移出候选集，不得进入生成阶段。

## 7. 内容验收与照片配额

每个主题至少保留 8 张合格候选图，再选择 3–4 张作为最终嵌入原图。

默认候选构成：

- 2–4 张人物与地标同框照；
- 2–3 张代表性大景；
- 2–3 张建筑、器物、门牌、票根或生活细节；
- 1 张能说明入口、路线或空间关系的照片（合适时）。

最终 4 张建议：

- 1 张人物主视觉；
- 1 张标志性全景；
- 1 张人物互动或生活场景；
- 1 张细节或补充视角。

博物馆、考古遗址、自然保护区可降低人物比例，但仍需真实现场细节。

每张入选图必须能回答：

- 这是哪个景点？
- 与当前主题有什么关系？
- 画面主体是什么？
- 在照片墙中承担什么叙事作用？

任一问题答不出，就不选用。

## 8. 生成前硬门禁

以下条件全部满足，才允许调用图片生成：

- [ ] 主题照片目录不为空；
- [ ] `来源.md` 记录至少 2 篇详情页笔记；
- [ ] 每篇笔记都有原始 JSON，且下载报告 `failed` 为空；
- [ ] 至少 8 张图片通过技术和视觉验收；
- [ ] 最终嵌入原图已逐张打开确认；
- [ ] `来源.md` 已写入“最终选图”及每张图的叙事用途；
- [ ] 左页事实能追溯到已读取笔记；
- [ ] 主题、页面标题、输出文件名完全一致；
- [ ] 不会混入其他主题或其他城市；
- [ ] 重做旧稿时已确定保留或替换策略；
- [ ] 已记录旅行底色、城市特色、故事场景和版面分工；
- [ ] 背景提示词包含具体场景、色彩、材质及正文与照片留白位置，不是通用牛皮纸模板。

门禁未通过时继续搜索或明确报告缺图，不能让生成模型凭空补照片。

## 9. 两阶段制作主题双页

### 9.1 生成无照片底板

先生成一张横向双页底板，严格落实1.1节的背景设计：

- 场景背景：围绕本次旅行的城市特色与故事环境，用水彩、版画、线描或纸艺建立丰富的远景和近景；风格按城市与实拍取色，不固定为棕色纸张。
- 左页：为故事标题和真实经历，或攻略标题和路线信息保留低对比、连续的正文区域；不要让大景和纹理穿过正文。
- 右页：3–4个纯白或透明的空照片框，保留相纸、胶带、阴影与图注位置。场景背景可围绕照片框展开，照片框内部必须为空。
- 中缝与材质：真实金属活页环、纸张厚度、接触阴影与适量撕边。皮面、纸色与装饰物服务于旅行主题。
- 城市与故事元素：在上缘、侧边、下缘或页间留白形成清楚可见的环境；不能只在角落放一个象征性小图标。
- 正文与图注建议生成时留空，后续用本地中文字体排入，避免错字和乱码。记录照片框坐标；背景重做后重新打开测量，不沿用失效坐标或旧排版。

底板提示词必须具体填写，不能把下列尖括号占位词直接发送给生成模型：

```text
实体皮面活页旅行手账双页、撕边纸、金属活页环与真实接触阴影；
城市与主题：<城市、具体地点与故事>；
旅行底色：<依据照片确定的色彩、天气、时间、光线和材质>；
丰富背景：<远景环境>、<近景场景>、<与故事有关的生活物件>，
使用<水彩／版画／纸艺／线描>表现，场景在<指定区域>清楚可见；
正文区域<位置与尺寸>保持浅色、低纹理与连续留白，保证文字可读；
右页保留3–4个纯白或透明的空照片框，指定各框位置与尺寸；
照片框内部不得出现人物、风景、插画或占位文字；
填入真实照片后，城市与故事背景仍然丰富可见；
禁止无关美食、其他城市、网页UI、二维码、无意义英文和虚构地标。
```

舟山海岛背景应在照片框外明确呈现岛屿、大海和对应天气的天空，可结合岩岸、灯塔与海边物件；夜航故事使用夜海与夜空，阴雨故事使用实际阴天的光线。其他城市按自身特色选择场景，不照搬舟山的海岛符号。

底板生成后先打开检查背景与留白，再合成照片。若场景缺失、背景仍然通用，或场景覆盖了正文区域，重新生成底板，不能以“之后照片里有风景”代替背景验收。

### 9.2 嵌入真实原图

底板生成后，用本机已有的图像工具（优先 Pillow、ImageMagick 或 Sharp；不为此新增依赖）把“最终选图”机械嵌入照片框：

1. 只允许等比缩放和居中裁切，不做生成式扩图或人物重绘。
2. 优先完整保留人物脸部、身体动作、地标名牌和建筑主体。
3. 允许轻微旋转以贴合相纸角度；不得改人物身份、服装和现场背景。
4. 原图水印若存在必须保留，不仿造、擦除或遮盖。
5. 左页文字和底板装饰不得覆盖照片主体。
6. 正式成品只能从“底板 + 已登记原图”合成，不把参考图再次交给生成模型重绘。

这一步是硬性要求：**参考图参与图片生成不等于使用真实照片。只有原图像素被嵌入最终 PNG，才算照片来源验收通过。**

人物照片额外要求：

- 写明“人物是照片主体，不能删除或替换为纯风景”。
- 不改变人物身份、服装、动作和主要背景。
- 标签只写已确认地点，不猜测机位。

## 10. 生成封面

整套只生成一张封面：

- 皮面颜色与材质延续本次旅行的底色，不固定为深棕；
- 清楚的城市名与简短副标题，可采用烫金、压印或手写排版；
- 围绕城市特色与故事环境，形成完整可见的场景背景，与内页保持同一色彩和材质体系；
- 标题仍是封面重点，场景层次丰富，不堆正文或攻略文字；
- 禁止混入其他城市符号。

## 11. 成品验收

生成后必须打开成品逐项检查。

### 文件与主题

- 文件名、页面大标题、页面内容属于同一主题。
- 不允许出现“园林山水文件里是胡同人文”一类串页。
- 正式文件位于 `<城市>/初稿/<主题>-双页.png`。

### 照片

- 照片墙是下载原图的机械嵌入，不是生成模型对参考图的重绘。
- 对照 `来源.md` 的“最终选图”，逐张确认文件名、人物、服装、构图和地标一致。
- 人物版中，每张人物照片的人物仍清晰可见。
- 照片框内部没有模型新增的假景点、假人物或错城画面。
- 没有纯风景替换人物、照片重复或关键主体被裁掉。

### 文字

- 标题和标签无明显错字。
- 景点名称正确，标签与照片对应。
- 交通、票价、时间等数字来自已读取内容；否则写“以官方当日信息为准”。
- 没有乱码、伪中文、无意义英文和二维码。

### 视觉

- 左页可读，右页照片为视觉重点。
- 活页环、中缝、撕边和阴影符合实体手账逻辑。
- 装饰不遮挡正文、人物脸部或地标主体。
- 同套页面材质一致，各主题有自己的识别色和故事场景。
- 背景有清楚可见的城市与故事环境，旅行底色与已核验照片相符；不是只替换标题的通用纸张模板。
- 临时遮住照片和标题，背景仍能说明这一页属于什么城市环境或旅行主题；背景不能靠实拍照片补足。
- 填入照片后，背景场景仍然可见；缩小预览和放大检查时，正文与图注都能读清。
- 背景插画与真实照片能够区分，地标外形准确，未伪造事实或混入其他城市符号。

不合格时重新生成。只保存文件不验收，视为未完成。

## 失败处理

- 小红书未登录或详情页不可访问：不下载缩略图，报告登录后继续。
- 详情页只有视频：继续寻找图文笔记；视频封面单独标记。
- 找不到合格图片：搜索同义词、入口名、地标名和机位；仍无结果时明确缺图，不生成假照片。
- 图片下载成功但内容错误：移出候选集，重新解析详情页。
- 成品主题串页：检查参考图、提示词标题和保存目标后重新生成；禁止只改文件名掩盖问题。
- 背景空泛或缺少城市特色：回到1.1节，补齐旅行底色与故事环境，重写提示词并重新生成底板；复用已核验原图，重新测量图框和排版，不重绘照片。
