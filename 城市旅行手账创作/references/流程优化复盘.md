# 上海手账流程复盘与技能优化

历史说明：以下十篇笔记相关记录仅描述旧流程。当前采集量以主技能为准：每个具体地方3篇有效笔记，其中至少2篇以女生旅行照片为主；不再执行每大主题十篇配额。

更新日期：2026-10-09。适用技能：`城市旅行手账创作`及其`小红书链接图片下载`依赖。

本次把实际暴露的问题落实为阶段顺序、明确的通过条件、恢复路径和两处脚本修复。保留每主题十篇有效笔记、全部正文图片归档、真实照片机械嵌入、作者与水印保留等要求；不靠减少素材要求解决执行困难。

## 1. 问题、根因与改善方案

| 实际问题 | 根因或缺口 | 标准处理与防复发条件 |
| --- | --- | --- |
| 旧封面缺少可核验照片来源 | 只看画面无法证明素材身份，旧稿审计不充分 | 先查源图、来源和合成记录；无法证明标“未核实”，不能凭外观认定模型照片。替换前保留旧版。 |
| 照片分散在14篇笔记的目录，重复整理费时 | 没有先按主题登记权威归档和选图路径 | 先建素材需求表，再引用实际归档；需要独立打包才重新归档。主题、noteId、报告路径在中断时一并保存。 |
| 搜索字段已输入，回车操作却持续失败 | 输入成功与搜索提交成功被当成一件事；继续用旧控件索引 | 输入后读新状态，优先点击实际搜索按钮；确认关键词对应的结果后再选笔记。失败时重新定位，不连续重试旧索引。 |
| 输入框/textarea变化、返回后仍在详情 | 页面布局与导航状态变化，没有重新观察 | 每次导航后确认URL/DOM；无法恢复搜索时在同一IAB开后台标签。继续保留IAB-only要求。 |
| 提取返回undefined；换包装又出现语法错误 | 带注释IIFE拼在return后，触发自动分号插入；字符串执行契约不一致 | 提取器改为单一完整函数表达式，原样静态回调；禁用动态包装、eval、new Function和临时替代提取器。先确认返回对象和N。 |
| 门牌415/425冲突 | 没有把精确信息的冲突作为定稿阻挡 | 记录双方依据，无法核实就使用已确认街道名；不能择一个数字装成确定事实。 |
| 往年秋景、叶色时间冲突 | 发布/编辑日期、拍摄日期、读取日期混用，历史图被误当实时信息 | 日期按页面原文保存，缺年不补年；旧图说明是参考，动态条件改为出行前查看实况。 |
| 重复图、拼图、圣诞装置、无关细节混入素材 | 只按下载成功判断能否入选，缺少逐图内容门禁 | 全部图片联系表筛查；所有候选、最终图与疑图单独打开。逐文件写具体原因，不批量填“关联弱”。 |
| 两页各8张候选未全部逐张打开 | 联系表筛查替代了候选细节检查 | 联系表负责全图筛查；全部候选必须单独核对主体、地点、水印与可用构图，再选每页3–4张。 |
| 生成照片框比例宽于原图 | 提示词设计与实际照片比例脱节 | 先选图再定框比例，生成后测内框；默认contain与相纸留白，保留人物、地标主体和水印。 |
| 第二页首版文字压到树枝 | 用预计坐标直接排版，缺少实际净空测量 | 打开当前底板，测正文净空和禁覆区，再试排；先移文字或改行宽，净空不足才重做底板，重做后重测。 |
| 作者名的相机emoji变方框 | 字体覆盖未经预检 | 用全部实际文字做样张；装饰emoji可省略但保留原作者名记录，实际汉字缺失必须换字体/回退。 |
| 打印图像生成完整结果导致巨大Base64输出 | 把结果对象当普通日志，缺少输出约定 | 只展示图像与路径/尺寸等短元信息，禁止打印完整对象或Base64。 |
| 两主题复用了同一组10篇，没有20篇独立来源 | 跨主题复用未在规划时明确，主题引用数与整套独立数混算 | 每主题仍独立列10个有效noteId与具体贡献；允许相关交叉引用时提前登记。整套取noteId并集，不能宣称复制就是新增来源；最终照片默认跨主题不重复。 |
| 第二主题复制目录后，报告仍指第一主题 | 复制文件与重新建立来源链混为一谈 | 优先原位引用并写真实路径；独立打包使用 `--reuse-report`，重新hash/解码并生成当前组报告，不复制旧报告冒充新报告。 |
| 历史Downloads可能消失，阻碍已有照片复用 | 把临时文件当唯一可信来源，忽视已经核验的归档 | 复用旧报告里的绝对归档路径，并对照noteId、index、URL、hash；临时Downloads不必存在，归档被修改或缺失仍应失败。 |

## 2. 提炼后的标准流程

每一步只留下必要产物。条件不通过时回到对应步骤，不因局部失败重新下载或生成整套。

1. **审计目录和旧稿。** 确定正式输出目录；工作区已是城市目录时直接用`初稿/`，避免城市目录重复嵌套。旧稿来源不明先记录，替换前备份。
2. **规划主题和来源集合。** 每主题定义故事、事实、照片角色、季节与背景；明确是原位引用还是独立归档。登记各主题十篇名单与整套去重计数。
3. **做IAB小样预检。** 一篇详情确认身份和N，完整原函数返回记录；第一张实际下载、解码、落盘成功后扩展。部分报告不能当整篇通过。
4. **完成采集、下载或核验复用。** 每篇全部正文图片归档；保留原始JSON、浏览器记录、来源和采用报告。N与保存位置一致、无失败、实际路径与hash可查才通过。
5. **技术验收和全图视觉筛查。** 对全部位置检查解码、尺寸、hash、重复；联系表覆盖全部图，候选全部单独查看。每主题至少8张合格候选，再选3–4张不同角色的照片。
6. **核事实、定正文、试字体。** 精确数字与日期有依据；不同作者经历分开；全部实际文字可显示，实际字体测量可排入。
7. **设计并生成空底板。** 一主题一张横向双页，背景与城市/故事一致，正文与照片内框空白。返回后打开检查，测真实内框、文字净空、图注区与禁覆区。
8. **试排并机械嵌图。** 默认完整等比适配；登记源hash、处理方式与实际坐标。打开预览检查遮挡，运行最小像素对照检查。
9. **统一封面、复核和交付。** 文件名、标题、主题、来源、事实、正文、照片和背景逐项一致；区分独立来源、主题引用、图片位置、hash去重、候选和最终数量。缺口明确列出。

主技能保存具体字段与每阶段门禁，本文件保存问题和原因；下载逻辑仅由依赖技能维护。这样避免两个技能各自出现一套提取和下载实现。

## 4. 实际验证与限度

- **提取自测**：`node scripts/test_extract.cjs`，通过。
- **下载与复用自测**：`python3 scripts/download_xhs_images.py --self-test`，通过。断言包含源归档已被修改时必须失败，不能由已存在的目标照片掩盖。
- **真实IAB详情**：noteId `6968d21e000000002202196a`，标题“在上海梧桐区拍出电影感（附路线图”。静态回调文本与源文件对照一致；页面显示18张，返回18张，noteId一致。未以本地字符串测试代替浏览器测试。
- **真实上海归档复用**：同篇18张旧归档在临时新主题目录完整导入；每张SHA-256正确，报告与原始JSON指向新组，复用依据指向旧归档。原目录未改动，验证临时目录自动清理。

本次验证脚本执行和归档路径，未重新运行整套手账创作、重新下载全部笔记或把旧成品宣称已按新标准验收。字体样张、候选逐图、城市背景与成品视觉仍需要每次执行时实际检查；规则不能保证网站未来DOM永远不变，变更时须重新做IAB预检。

## 5. 备份与维护原则

修改前的五个文件分别保存在两个技能目录的 `.history/2026-10-09-流程优化/`，保持原相对路径并加`.bak`。备份包含用户本次优化前已有的修改；没有回滚其他Git改动。

今后修改共用提取/下载函数先查所有调用方，维护一份实现。运行现有自测，再做一篇真实IAB契约验证；仅报告实际检查通过的范围。新问题优先补到对应阶段与本复盘表，不堆叠新的工具或重复检查流程。

| 用户反馈或本次遇到的问题 | 根因 | 最终规则 |
| --- | --- | --- |
| 单张26.5×18.5cm，但像素2185×3130；还需要双页皮面载体 | 单页宽高与外围展示画布混用 | 单页18.5宽×26.5高，2185×3130；两张竖页组成跨页，载体另计 |

新增技能内封面与两张最终效果预览作为视觉基准；预览不作为历史成品物理尺寸已合格的证明。历史上海稿未因本次技能更新被覆盖。
