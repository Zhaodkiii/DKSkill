# 小鲸正文配图

## 核心定位

为中文文章设计和生成 16:9 横版正文配图。若任务包含文章封面，则封面默认生成 3:4 竖版，正文配图仍保持 16:9 横版。目标不是做商业插画、PPT 信息图或儿童贴纸，而是把文章里的关键判断、流程、结构、状态或隐喻，变成一张清爽、圆润、有记忆点、可读但不说明书的动画人物解释图。

默认视觉 IP 是“小鲸”：天蓝色圆润蓝鲸动画人物，白色竖纹肚皮，粉色脸颊，短手短脚，尾鳍，头顶水滴喷泉。小鲸必须参与画面的核心动作，不能只是站在旁边当装饰。

小鲸的单词识别点是：**喷泉**。每张图都要保留头顶水滴喷泉或与喷泉相关的动作暗示，避免角色漂移成普通蓝色小动物。

这个 skill 的默认交付目标是：让正文读起来更清楚，而不是把文章做成画册。优先画“读者最容易卡住的认知节点”，并把生成结果直接整理进文章所在目录，便于后续发布、迁移和预览。

## 先读这些参考

按任务需要读取，不要一次塞满上下文：

- `references/style-dna.md`：风格 DNA、颜色、文字、禁忌。
- `references/little-whale-ip.md`：小鲸 IP 的形象、识别点、动作库和禁忌。
- `references/composition-patterns.md`：结构类型、原创隐喻方法和反复刻规则。
- `references/prompt-template.md`：单张生图提示词模板。
- `references/qa-checklist.md`：生成后检查和迭代规则。
- `assets/examples/`：只作低频视觉校准，不进入默认生成路径。不要照抄这些案例的构图、物件或标注。

## 工作流

### 1. 消化正文

先读用户给的正文、链接、Notion 页面、Markdown 文件或截图内容。若是本地 Markdown 路径，先完整读取正文，不要只看标题。提炼：

- 核心观点是什么
- 哪些段落承担认知转折
- 哪些内容适合用图解释
- 哪些地方只适合文字，不需要图

不要平均配图。优先选择“认知锚点”，例如：核心判断、两个断点、输入输出闭环、分流、前后对比、一鱼多吃、承接路径、常见坑、角色状态变化、报告解读中的分工、趋势、风险信号、复诊提问清单。

常见插图位置：

- “先说结论”之后：放核心判断图。
- 一个概念解释完之后：放概念隐喻图。
- 一个清单或表格之后：放问题卡、资料包或归纳图。
- 风险信号段之后：放提醒收束图。
- 参考来源前通常不再额外配图，除非正文最后一段本身是行动提醒。

### 2. 先出配图策略

如果用户只是说“分析怎么配图 / 思考哪些地方需要配图”，先给 shot list。每张图写清楚：

- 放在哪个段落后
- 图的主题
- 核心意思
- 结构类型
- 小鲸在图里做什么
- 建议元素
- 建议中文标注词

默认 2-5 张。文章很短时 1-2 张；长文也要优先控制在 5 张以内，除非用户明确要求更多。够用就好，避免把正文做成画册。健康科普、报告解读、就医指南类短文，通常 3-5 张足够：总览、核心分工、关键判断、风险提醒、复诊/行动清单中择要取舍。

### 3. 单张生成

如果用户明确要求“生成 / 输出 / 做图 / 帮我生成”，不要停下来等确认；用内置 `image_gen` 每张单独生成。不要把多张图拼在一张里。

每张图只讲一个核心结构。提示词必须包含：

- 16:9 横版中文正文配图
- 纯白背景
- 蓝白圆润动画人物风格，细腻高光，干净边缘
- 少量红色/橙色/蓝色中文手写批注
- 大量留白
- 小鲸作为核心动作主体
- 保留“喷泉”识别点
- 禁止小黑、黑色怪物、PPT、商业海报、儿童贴纸、复杂架构、左上角类型标题

如果用户要求同时生成文章封面：

- 封面单独生成，不和正文配图拼在一张里。
- 封面默认 3:4 竖版，提示词必须包含“3:4 竖版中文文章封面”。
- 封面可以比正文配图更聚焦主题气质，但仍保持纯白清爽背景、小鲸 IP 识别点和少量中文短标注。
- 正文配图数量仍按 2-5 张控制；封面不计入正文配图数量。

不要复刻过往案例。案例只提供风格密度和角色参与方式，不能直接复用“传送带断点 / 角色拉线 / 素材鱼 / 盖章工具箱 / 常见坑路径”等已有构图，除非用户明确要求复刻某张图。每次都要从当前文章重新发明一个清爽但成立的隐喻。

生成时的习惯：

- 每张图只讲一个判断，不把一整段表格塞进一张图。
- 中文标注宁少勿多，优先 3-6 个短词。
- 小鲸必须承担动作：收拢、测量、分拣、写卡片、守门、指路、比较、检查、托举。
- 医疗健康主题要温和抽象，不画血腥、恐怖、真实病灶或复杂解剖。
- 报告解读类图可以多用“资料夹、卡片、显微镜、标尺、问诊卡、时间线、对比片、提醒路牌”等轻量物件。
- 不要在画面左上角写“流程图、路线图、系统架构图、常见坑”等类型标题。

### 4. 检查与迭代

生成后检查 `references/qa-checklist.md`。如果出现以下问题，优先重生成或局部编辑：

- 小鲸只是装饰
- 画面太满
- 太像流程图/PPT
- 中文太多或错字严重
- 左上角出现“常见坑/流程图/系统架构图”等标题
- 小鲸缺少喷泉识别点、肚纹、短手短脚或尾鳍
- 画风太幼稚、死板或像贴纸素材
- 背景不是干净白底

如果一次生成出现多个候选图，要挑最稳的最终图，不要把重复、文字错得多、太像 PPT、或小鲸识别点弱的候选插入正文。必要时用本地图片查看工具逐张检查。

### 5. 保存和整理

保留原始生成文件，不要删除生成器输出目录里的原图。若需要交付到另一路径，一律复制，不要移动原图。

#### 本地 Markdown 文章默认目录格式

当用户给出本地 Markdown 文件路径，并要求“继续”“直接插入”“以上目录格式输出”“放到文章目录”等，默认按下面规则执行：

1. 在 Markdown 所在目录下创建一个同名目录，目录名去掉 `.md` 后缀。
2. 将原 Markdown 移动到这个同名目录内。
3. 将最终选中的 PNG 图片复制到这个同名目录根部。
4. 不创建 `附件/`、`assets/`、`images/` 等子目录，除非用户明确要求。
5. Markdown 图片链接使用同级相对路径：

```text
![图片说明](01-topic-name.png)
```

6. 插图放在对应段落后方，不集中堆在文末。
7. 完成后核对：目录里有 Markdown 和 PNG；原上级目录不再残留同名 Markdown；正文里没有绝对路径、`generated_images`、`附件/` 或其他旧路径。

示例：

```text
/文章所在目录/
  03_文章标题/
    03_文章标题.md
    01-topic-name.png
    02-topic-name.png
    03-topic-name.png
```

#### 文件命名

图片按正文出现顺序命名，使用两位数字加英文短 slug：

```text
01-core-judgment.png
02-topic-role.png
03-risk-signal.png
```

命名要能表达用途，避免 `image1.png`、`final.png`、`插图.png`。若同名文件已存在，不要覆盖，先检查是否是本次目标；必要时换更具体的名字或询问用户。

#### Workspace 交付

如果用户只是要生成图，不要求插入某篇本地文章，可以把最终图复制到 workspace：

```text
assets/<article-slug>-illustrations/
```

但只要用户给的是本地 Markdown 文章，并且上下文在整理知识库文章，优先采用“同名目录 + 图片同级 + 相对路径”的格式。

## 输出口径

生成前的策略输出要短而准。生成后的交付要包含：

- 生成了几张
- 每张图的用途
- 保存路径
- 是否已插入 Markdown
- 是否已核对相对路径
- 哪些图最稳，哪些图是可选（仅在有候选差异时说明）

不要长篇解释风格理论；让图自己说话。

如果用户明确说“只更新 skill / 不生成图片”，只修改 skill 文件，不调用 `image_gen`，不移动文章，不创建配图目录。
