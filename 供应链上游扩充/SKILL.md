# 新能源汽车供应链 · 上游扩充

## 何时使用
用户需要对《新能源汽车供应链整合数据模型_品牌关联.xlsx》做上游供应链扩充：新增产品、企业、供应链关系、来源证据。典型触发词：扩充 / 新增品类 / 新增产品 / 补供应商 / 上下游梳理 / 关联企业。

## 核心纪律（最高优先）
- **只追加，不动原行**：动手前先复制备份到 `历史备份/`；交付前与备份逐格比对，原行 0 差异。
- **不新增品类节点，只新增产品**：归属ID 一律挂 产品归属 现有树节点；某产品无完全匹配叶节点就挂最近父节点并在产品说明注明。
- **正确顺序**：先建企业档案 → 再产品表新增产品（关联企业）→ 再供应链核心建立上下游关系（零部件引用产品表）。
- **事实可追溯，严禁编造**：供应商/产品/来源/URL 必须来自真实可核验检索；区分 A(官方)/B(媒体/公告)/C(线索待核验)，查不到一手来源按 C 级并如实标注。
- **归属ID/名称一致**：供应链核心、产品表的归属ID与归属名称取自 产品归属 树，保持一致。

## 流程节点

### 节点0 · 前置：读模型 + 备份
1. 用 openpyxl 读取 xlsx，确认 10 个 sheet、表头行位置、现有最大编号（ENT/PRD/REL/WEB/AUD）。
2. 复制一份备份到 `历史备份/`（回滚快照）。

### 节点1 · 分类定位：目标品类 → 归属节点
1. 扫描 产品归属 定位目标品类对应归属ID/叶节点（不新增）。
2. 明确需求方（需方）实体（如小米 ENT-0001、理想 ENT-0065、CATL ENT-0003）。

### 节点2 · 全网调研：企业/产品/来源
1. 按「品牌 × 品类 × 来源类型」拆多个 query 并行搜索（一次≤3个 query）。
2. 定位实际供应商、对应产品、真实来源 URL；关键页用 web_fetch 精读核验。
3. 证据分级 A/B/C；车型范围能落到具体车型才写，写不了用“小米(未指定车型)”等既有写法。

### 节点3 · 建立企业档案（企业表）
新增供应商 ENT 编号（延续现有最大+1），至少填：统一企业ID、企业全称、简称/品牌、供应链角色、国家/地区、所属集团、状态、业务说明、原始企业ID、来源编号。已有企业直接复用（如经纬恒润、英飞凌），不重复建档。

### 节点4 · 登记证据来源（证据与核验）
每条来源登记：统一来源ID（可空）、来源工作簿、原始来源编号（如 WEB-xx）、来源类型、发布方、文件/页面标题、发布日期、可验证事项、原始URL、访问/授权、状态。

### 节点5 · 产品表新增产品
为每个具体产品建 PRD 记录（延续现有最大+1）：归属ID 挂现有树节点，填归属名称/产品路径；**关联企业**——企业ID(col17)/企业名称(col18) 指向供方企业。产品名称写 `=HYPERLINK("#'产品表'!A{行}","{名称}")`，企业ID写 `=HYPERLINK("#'企业表'!A{行}","{企业名称}")`。

### 节点6 · 供应链核心关联（上下游梳理）
建 REL 关系（延续现有最大+1）：供方企业ID/需方企业ID、供方企业/需方企业（超链接到企业表）、归属ID/归属名称、零部件（`=HYPERLINK("#'产品表'!A{行}","{零部件名}")`）、车型/版本、层级、关系类型、证据等级、核验状态、有效起始/结束、公开关系摘要、来源编号、来源跳转。

### 节点7 · 审计登记（时效与审计）
为本次扩充新增 AUD 记录：日期、事件类型=供应链上游扩充、对象类型、关联对象、处理状态、责任角色=研究员、说明。

### 节点8 · 来源清单 / 总览更新
来源清单新增该来源工作簿行（或累加既有行）的导入企业/产品/关系/证据/审计数；总览对应指标累加。

### 节点9 · 自检验证 + 交付
1. 与备份逐格比对：10 个 sheet 原行 0 差异（只追加）。
2. 逐列对齐、归属一致、来源可回链、超链接可点（用 `scripts/verify_expansion.py` 校验）。
3. 用 `present_files` 交付更新后的 xlsx 路径 + 交付说明（新增企业/产品/关系/证据数、A/B/C 分布、待核验缺口）。

## 资源
- **结构规范**：见 `references/schema.md` —— 10 个 sheet 的列位、编号规则、超链接约定、取值集合、常用归属节点、关键企业ID。写库前先读。
- **写入器**：`scripts/append_expansion.py` —— 按 payload JSON 批量追加企业/证据/产品/关系/审计，自动续号、写超链接、先备份、只追加。见其 `--help`。
- **校验器**：`scripts/verify_expansion.py` —— 对照备份断言原行 0 差异、新增行结构/超链接/编号连续性正确。

## 步骤速查
1. 备份 → 2. 定位归属节点 → 3. 调研(拆query并行,分级A/B/C) → 4. 建档(企业表) → 5. 登记来源(证据) → 6. 产品表新增产品(挂节点+关联企业) → 7. 供应链核心关联(零部件指向产品表) → 8. 审计 → 9. 来源清单/总览 → 10. 校验交付。
