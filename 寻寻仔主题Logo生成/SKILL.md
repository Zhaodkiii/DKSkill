# 旅行主题 Logo 生成

## 目标与默认范围

生成一张可直接叠加到旅行手账、照片或排版里的独立主题 Logo PNG。
“融入主题”指把主题意象融入 Logo 的图形语言；成品画布只有 Logo，不包含园林照片、手账页面、纸片或场景。
必须以用户指定的基础图形 Logo 为骨架，在其基础上增加主题意象。打开的书、双眼、虚线路线和红色终点必须保留，主题不能替换掉基础 Logo。去掉品牌文字不等于去掉品牌图形。

每次用户请求最多调用一次图像生成/编辑工具，只生成一张纯图形 Logo，不含「寻寻仔」「TRAVEL DIARY」、地点文字、主题标题或其他文字。用户明确要求主题文字时才加入其指定内容，不能自动补入产品品牌字标。

**单次生成硬限制**：不批量生成、不生成候选方案、不自动修正或重试、不因不满意或验收失败再次调用工具。调用报错或返回结果不明确时也不重复调用，先如实说明本次状态。只有用户后续明确要求重新生成或修改，才开启一次新的单张生成。

## 一、生成前必须实际读图

1. 获取用户提供的主题图片路径或附件。只有目录时先列出图片文件，从用户指定范围找到相关图片；不自行选择无关主题。
2. 用当前可用的图片查看工具打开每一张主题图。本地文件使用 `view_image`；有跨页和左右单页时三张都看。
3. 读取尺寸、格式等元数据只用于规格判断，不能代替视觉查看。文件名、目录名、之前的聊天结论也不能代替看图。
4. **每一次图像生成调用前**，都必须用图片查看工具重新打开 `/Users/hua/Documents/project/TravelDiary/Logo/exec-fd7f47de-2f66-48cd-a4f5-7266e5c63169.png`，实际检查书本、双眼、路线、红点与线条。首次生成及用户后续明确要求的修改、新版本或重新生成都执行这一条；同一请求不连续生成，也不自动修正或重试；刚才已经看过也不能省略，不复用缓存、缩略图、附件副本或历史读图结论。用户另给样式参考时另行查看。原文件缺失或无法打开时暂停生成，解决原文件读取问题后继续，不能自动改用副本或凭记忆创作。
5. 参考图缺失、无法打开或关键主体不可辨认时，先解决文件读取问题。仅在无法继续时请用户提供正确文件，不得凭记忆生成。

## 二、确认主题，区分事实和判断

读图后提炼以下项目，并用简短说明向用户展示：

| 项目 | 必须具体说明 |
|---|---|
| 地点或对象 | 依据用户信息、画面可读文字或可辨认主体；不把普通亭台武断认成具体园林 |
| 核心主题 | 画面重点表达什么，例如池水倒影、花窗借景、海岛灯塔、山城街巷 |
| 视觉证据 | 至少列出两项真实可见元素，说明主题为什么成立 |
| 风格 | 摄影/线描/水墨/拼贴的组合、纸张或材质表现、线条特征与疏密 |
| 配色与气氛 | 主色和点缀色，静谧、明亮、怀旧等可见氛围 |
| 可入 Logo 的意象 | 选择一至两个最具辨识度的元素，最多三个；说明如何简化 |

例如：照片是实景摄影，周边有水墨纹样时，应说“实景照片与水墨纹样结合”，不能把照片整体称为水墨画。
标题可以核对主题，但不能只复述标题。多图主题不同则分别判断，不强行合并。

### 主题确认的执行规则

- 用户已指定主题，图片与指定主题一致：直接按此主题继续，说明读图结果，不再重复请求批准。
- 用户要求“先确认主题再生成”，且尚未认可主题：先交付读图判断，等待主题确认后生成。
- 用户直接要求生成，主题清楚：展示读图判断后继续执行，不额外增加确认环节。
- 图像与用户描述冲突、多个主题难以取舍，或地点不确定且会影响 Logo：询问一个必要问题；等待答案期间可整理已读图片的风格与配色。
- 在对话中说明主题结论的来源：用户指定 / 用户已确认 / 图片支持的判断。未经用户明确认可，不写“用户已确认”。

## 三、锁定基础样式，再确定主题改动

生成前先逐项核对基础图形，再说明主题意象的融入位置。

| 必须保留的基础 | 要求 |
|---|---|
| 打开的书 | 横向双页、弯曲上沿、中央书脊、底部 V 形折页、外层书页轮廓，比例与原图接近 |
| 两只眼睛 | 左右页各一只竖向椭圆眼睛，位置与大小关系稳定，不被主题覆盖 |
| 虚线路线 | 圆头分段线形成微笑状弧线，横跨左右书页；保持起伏、弧线和分段特征 |
| 红色终点 | 右页一个朱红圆点，保持旅行终点语义，不删除或变成多个红点 |
| 线条风格 | 厚实、圆润、平面、简洁；主题新增线条与原图统一，不突然变成复杂写实插画 |
| 色彩 | 默认深绿主体与朱红终点，参考原提案色板为 #173F32 与 #A63A2B；主题点缀色少量使用，不替换基础主色 |
| 留白 | 书页空白与图形外部最终透明，基础图中的米色展示底不复制 |
| 文字 | 默认完全无文字，保留图形不包含「寻寻仔 / TRAVEL DIARY」字标 |

允许的主题变化：书页内添加一至两个简化意象、少量水纹或线描、与书页轮廓自然衔接的小幅造型变化。即使加屋檐，仍须明显认出打开的书。
禁止的主题变化：用亭台、灯塔、花窗或山形替代整个书本，删掉双眼或路线，改成另一个品牌图形，在 Logo 周围堆场景与装饰。

## 四、在基础图形上融入主题

1. 写出设计目标，例如“保留原书本、双眼、虚线路线和红点，在书页中融入留园亭台与池水倒影”。
2. 从实际主题图选一个主意象、最多一个辅意象；明确新增部位以及保留的基础结构。
3. 优先使用书页内空白区，让主题线条避开眼睛、书脊、虚线路线和终点；主题只能辅助识别，不压过基础主体。
4. 如将路径与水纹结合，仍须保留可辨认的圆头虚线弧线，不能整条替换成实线水波。花窗只能局部修饰书页，不替换书本轮廓。
5. 主题图的复古氛围转译为简练线描和少量局部纹样；纸张撕边、实物阴影、拍照光线不进入透明 Logo。
6. 缩小至约 160 px 宽时，首先能认出同一个基础书本 Logo，再能感知主题。细节过多就减少主题装饰，不删基础识别项。
7. 检查整个图形无品牌名、英文或未经用户要求的文字。

## 六、验收：结构检查和视觉检查都必须做

### 1. 文件与 Alpha 检查

使用脚本检查，并在临时目录合成同一结果的白底、深色底、棋盘格检查预览。这些仅供内部检查，不调用图像生成工具、不产生新 Logo、不作为多张成品交付：

```bash
python3 "/Users/hua/Documents/Skill/寻寻仔主题Logo生成/scripts/inspect_logo.py" \
  "生成图的实际绝对路径.png" --preview-dir "本次任务临时验收目录"
```

必须确认真实格式为 PNG，有 Alpha 通道，存在全透明像素和可见前景，四边没有 Logo 笔画被截断。
不能仅凭 `RGBA`、四角透明、文件扩展名或工具的“透明”描述宣布通过。
脚本结构检查通过不代表视觉合格。

### 2. 实际打开三种底色预览

- 白底：主体轮廓与主题细节清楚，画布无大片灰雾或纸张残留。
- 深色底：辨别边缘光晕、白色毛边、矩形残底；深色图形与深色底对比低是颜色特性，不以此强制改色，重点看是否出现异常残留。
- 棋盘格：Logo 周围和内部留空区是真实透明，棋盘格来自验收预览而非被画进成品。
- 对照基础图：逐项核对打开的书、中央折页、两只眼睛、圆头虚线路线、右页单红点、深绿粗圆线条。任一核心消失、被覆盖或明显变形都判不合格。
- 对照主题改动：主题是基础图上的局部增加，不能只剩亭台、花窗、灯塔等主题剪影。
- 对照主题：一至两个主题意象清楚，风格相容，主体未变成复杂风景插画。
- 检查文字：默认成品中没有任何文字；尤其不能出现「寻寻仔」或「TRAVEL DIARY」。用户明确要求主题文字时，逐字核对其指定内容。
- 缩小查看：约 160 px 宽时检查图形识别；用户要求的文字可读性另按实际使用尺寸判断。

### 3. 不合格时停止生成

发现光晕、半透明雾状背景、景物、纸片、假棋盘格、基础骨架缺失、未经要求的文字或主题不符时，在对话中说明具体问题，结束本次生成，不自动修正或重试。
仅将符合要求的结果称为成品；本次结果不合格则如实说明，保留工具原文件，不将其作为合格成品存档。不擅自用色键抠图或缩放掩盖问题。
只有用户之后明确要求修改或重新生成，才再开启一次单张生成；调用前重新读取指定基础原文件，生成后验收一次。
